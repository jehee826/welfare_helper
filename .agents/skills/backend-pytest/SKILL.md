# 백엔드·RAG 검사

최신 업데이트: 2026-11-07 14:34 KST

1. 해당 태스크와 BackEnd.main:app의 관련 호출 경로·소비자를 읽는다. 자신의 작업 루트·담당 브랜치·허용 경로를 확인한다. Python/의존성은 .python-version·pyproject.toml·기존 잠금/환경에서 확인하고 불필요한 새 환경을 만들지 않는다.
2. 검색어 준비→검색 점수/권한→전달 원문/버전→생성→응답 계약을 분리해 원인을 확인한다. 저장 프로필·옛 챗봇 추정을 사용자 조건이나 사실 근거로 넣지 않는다. 일반화된 지침과 계약의 최소 수정으로 해결한다.
3. API/DTO 변경은 확장·관리자 담당과 먼저 맞춘다. 요청/응답·기본값·오류·구버전 호환을 기록하고 서버 PR이 main에 병합된 뒤 클라이언트 담당이 그 기준을 받아 연결한다. 미병합 상대 브랜치 코드를 임의로 복사하지 않는다. 코드의 권한·개인정보·입력예산·기한/취소·공통 gate·출처/문서 버전 경계를 유지한다. 실패 원문·비밀을 오류나 로그에 노출하지 않는다.
4. 실제 DB/모델 연결 없는 집중 pytest를 기본으로 한다. 필요한 정상 흐름과 확인된 결함만 검사하고 구현 문자열을 그대로 단언하는 시험을 늘리지 않는다. 실제 데이터 쓰기는 대역으로 분리하고 운영 변형으로 검증하지 않는다.
   협업 계획4절의 환경파일 미사용 진입과 태스크별 검사 목록을 따른다. Settings 생성 전에 env_file을 끄고 상속된 운영 설정을 시험 프로세스 안에서 격리한다. 기존 스크립트의 전체 CI 실행을 매번 대신 돌리지 않는다. 새 계약·파일은 계획의 신규 예정과 구분하고 서버 PR 병합 전에 확장 구현을 완료로 보고하지 않는다.
5. 명시된 실제 모델 시험은 질문·자료 버전·설정·호출 상한을 고정해 첫 출력을 보존한다. 준비/검색/생성 실패를 구분하고 같은 문항을 무제한 재시도하지 않는다. 예상 답변을 모델 입력에 넣지 않는다.
6. 실행한 명령/결과·미검증 소비자·운영 미반영을 구분해 설계에 전달한다. 시험용으로 시작한 프로세스만 정리하고 기존 서비스는 유지한다.
