# Supabase·문서 자료

최신 업데이트: 2026-11-04 12:50 KST

1. 승인된 프로젝트/런타임 대상과 문서 범위를 현재 서비스 메타데이터로 재확인한다. 실제 .env·키·접속 URI의 비밀 부분은 읽거나 출력하지 않는다. 공식 문서/실제 제공 도구로 버전 의존사항을 확인한다.
2. 문서 조회는 읽기 전용부터, 쓰기는 해당 작업 승인과 제도/문서ID·해시·버전·관련 작업·게시 참조를 확인한 뒤 지정된 한 담당자가 한다. 별도 브랜치/clone은 DB를 격리하지 않는다. 다른 담당의 적재·삭제·모델 평가 중 변경을 겹치지 않는다. test_only 표시만으로 삭제 대상을 정하지 않는다. 테이블·관리자·사용자 상담·무관 자료를 보존한다.
3. 동일 자료 중복 여부와 기존 처리/교체 경로를 먼저 확인한다. 업로드→Docling→청크→실제 임베딩→게시 각 단계를 구분한다. 현재 모델의 실제 차원을 확인하며 고정 벡터로 성공을 대체하지 않는다. 정답표·시험 결과는 적재하지 않는다.
4. 교체/삭제는 백업·참조 일관성·worker lease/재게시 경쟁·실패 시 기존 게시본 또는 복구 순서를 준비한다. 사전 검증만 성공했다고 원본부터 지우지 않는다. 원자 처리 가능한 부분은 트랜잭션 경계로 묶는다.
5. 서버 전용 키·역할과 공개/비공개 권한을 유지한다. client 직접 사용자 데이터 접근이 생길 때만 소유권/RLS를 설계하며 요청하지 않은 Auth/스키마 변경을 포함하지 않는다. SQL은 매개변수화하고 실제 패턴에 필요한 쿼리/인덱스만 검토한다.
6. SELECT 1은 연결 확인일 뿐 정책·문서 적재 성공이 아니다. 작업 상태·활성 문서 버전·고아 참조·실제 검색을 확인한다. 관리자 UI 시작 시험과 서버 직접 적재를 따로 보고한다.
7. 승인 확인창 만료와 거절을 구분한다. 만료 재요청은 사용자 지시/유효 승인과 도구 정책 안에서 제한적으로 처리하고, 거절은 다른 경로로 우회하지 않는다. 부분 실패 상태와 보존/복구 결과를 남긴다.
