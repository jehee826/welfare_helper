# 확장 화면 상담 인계

현재 제품 경로는 `Extension/`의 unpacked MV3 Chrome 확장이다. Desktop/Electron 앱·제품용 UIA 수집기는 실행하지 않는다. 실제 UI 테스트 도구는 기존 일반 Chrome을 조작하는 PowerShell UIA·Win32다. 실행·EC2 전환 절차는 [확장 README](../Extension/README.md)를 따른다.

## 한일

- **목업 검색 자료 교체 완료:** 테이블·트리거를 변경하지 않고 기존 테스트 문서 5개를 한 트랜잭션에서 삭제해 연결 작업 5개·벡터 24개를 기존 FK로 함께 정리했다. 현재는 새 가상 MD 문서 1개·성공 작업 1개·벡터 7개만 남는다. 제도 3개·부서 3개와 관리자·Auth 데이터는 전후 행 지문이 같으며 새 문서/작업/벡터도 그대로 보존됐다. 원본 보존 비게시 SQL은 적용하지 않았고 검토용 파일도 제거했다.
- **Terra 교체 후 런타임 검증 통과:** 관리자 저장소 스냅샷은 새 문서 청크 7개만 반환하고 unavailable은 없다. 원본 해시·전체 블록/청크 span·출처 validator·1024차원 검증과 관리자 로그인 200→실제 문서 검색 200(7개 결과·블록 출처 있음)→로그아웃 204를 확인했다. 익명 스냅샷은 테스트 문서·제도를 계속 제외한다. 생성 요청은 보내지 않았다.
- **확장 문서 관리자 연결 추가:** 옵션의 비밀번호 입력으로 기존 `/api/v1/admin/login`을 사용하고 `/session`·`/logout`을 재사용한다. 비밀번호 입력은 전송 직전에 비우고 저장하지 않는다. 관리자 토큰은 별도 `storage.session.documentAdminSession`에만 보관하고, 문서 `/chat`에만 사용한다. 화면 상담은 기존 확장 토큰, 일반 문서는 익명 요청을 유지한다. content script·페이지 DOM·연결 JSON·로그에는 관리자 토큰을 보내지 않는다.
- 로그아웃·401/403·만료는 관리자 토큰과 진행 중 문서 요청·문서 이력/근거를 정리하며 화면 상담을 유지한다. 만료 토큰은 다음 확인/요청에서 제거하고, 관리자 선택 상태의 만료는 재로그인을 요구해 익명으로 자동 전환하지 않는다. 독립적인 비밀값 없는 접근 ID를 준비·전송 직전·응답 직전에 비교해 알림 누락·지연 시에도 다른 인증 상태에 이전 이력이나 답변을 넘기지 않는다. 로그아웃 시 로컬 토큰을 먼저 제거하고 서버 해제 실패는 옵션에 표시한다.
- **Terra 신규 관리자 검사 16개 통과:** 송신자 제한·토큰 격리·모드별 인증 헤더·비밀번호 즉시 삭제·로그아웃·만료/401·지연 무효화·접근 ID 불일치·알림 누락/응답 직전 인증 변경을 확인했다. JS 5개 문법과 diff 검사도 통과했다. 실제 일반 Chrome에서 최신 확장 로그인→관리자 연결, 로그아웃→익명, 재로그인→관리자 연결을 확인했고 현재 문서 관리자 모드와 이미지 off/600초 정상 연결을 유지한다. 실제 비밀번호 필드 값은 UIA로 읽지 않았으며 즉시 삭제는 모형 검사 근거다. 실제 패널 생성 답변·근거는 호출하지 않았다.
- 실제 공식 복지로 홈에서 화면 모드의 개발 검사로 ‘본문 바로가기’에 ① 파란 테두리·번호를 표시한 뒤 문서 모드 전환 시 둘 다 사라지는 것을 시각 확인했다. 관리자 연결 표시와 개발/이미지 도구 숨김도 확인했다. 이 신규 전환 검사에만 사용한 두 프레임은 삭제했고 모델·검색 요청을 추가하지 않았다.
- **새 가상 MD 적재·검색 완료:** `docs/design/rag-model-comparison-fixture.md` 하나를 기존 관리자 로그인·문서 업로드 API(202)로 접수하고 워커가 Docling MD 분석→청크→실제 bge-m3 임베딩→게시했다. 새 문서 ID는 `aa467e93-62e2-42f5-ba61-c1ab5ddf6fd1`, 성공 작업은 `4f03fcc7-77b5-4c76-a435-14ae9b5a3f42`다. 기존 `TEST_MOCK_LEARNING`에 연결했고 원문·문서의 가상 표시와 test_only=true를 유지했다. PDF 분석 검증은 아니다.
- Terra가 새 원본 SHA-256 `b15d605a9ed97dfb75e15fe4191605134e38d94c03f5d202032405018c21bfef`의 fixture 일치, 분석 24블록·본문 6절, 벡터 7개의 1024차원·양의 norm·bge-m3 digest를 확인했다. 기존 validator로 분석 해시·전체 블록 및 각 청크 span·출처 연결이 통과했다. 실제 관리자 로그인 200→문서 검색 200(7개 결과·블록 출처 있음)→로그아웃 204를 확인했다. 별도 answer-key는 읽거나 적재하지 않았고 실제 LLM/VLM 생성·답변 품질 평가는 하지 않았다.
- 익명 저장소 스냅샷에서는 새 문서와 테스트 제도가 제외된다. 패널도 익명 선택 시 목업을 조회할 수 없으며, 위의 명시적 관리자 연결을 사용해야 한다. 목업의 실제 관리자 검색 성공은 적재 검증 단계에서 확인했고, 이후 확장 관리자 연결 검증은 생성 호출 없이 수행했다. 현재 qa.py 최소 문서 근거 지침과 `/chat`→`answer_document` 경로는 그대로이며 옛 복지 주제·조건별 고정보류 지침을 복구하지 않았다.
- 문서 업로드 503은 등록 트랜잭션의 `ReadOnlySqlTransaction`(25006)이었고, 새 연결 기본값이 on/off로 달라지는 현상을 확인했다. `BackEnd/documents/store.py`에서 트랜잭션 시작 전 `set_session(readonly=False)`를 명시해 수정했다. DB 역할·기본 설정·권한은 변경하지 않았다. Terra 모형 집중 검사 7개로 등록·실패 롤백/닫기와 기존 검색의 REPEATABLE READ·readonly=True 유지를 확인했다. 기존 HTTP 인증 pytest는 대기 상태에서 중단해 통과로 계산하지 않았으며 실제 인증 업로드 성공과 구분한다.
- 백엔드·문서 워커에만 수정 이미지를 반영했고 세 서비스 healthy를 확인했다. Ollama ID `1dca3eccff8d`, 모델·캐시는 유지했다. 임시 업로드 실행기·원문 사본은 정리했다. DB의 기존 active_job_id 해제 금지 규칙은 그대로이며, 이번 자료 교체는 기존 문서 삭제·FK 정리 경로를 사용해 스키마 변경 없이 완료했다.
- **로컬 문서 질문 모드 구현:** `Extension/content.js`의 명시적 화면 안내/문서 질문 선택으로 전환 시 요청·테두리·현재 지시를 정리하고 모드별 대화·이력을 보존한다. 대화 지우기는 선택 모드에만 적용한다. 기존 화면 안내의 DOM·선택 이미지·0~3대상 계약은 유지한다.
- 문서 모드는 기존 고정 loopback `POST /api/v1/chat`에 query/history만 전송한다. 화면 수집·캡처·대상 ID 해석·이미지 옵션을 사용하지 않고, 숫자·연도·색/번호·HTML 문자를 화면 라벨 규칙으로 차단하지 않는다. 답변과 실제 evidence 원문·쪽·블록·출처는 textContent로 표시하며 검색 원문을 검증된 답변 인용으로 주장하지 않는다. 개발용 details만 숨겨 재전환 시 근거 details를 보존한다.
- 문서 요청의 기본은 확장 토큰·쿠키 없는 익명 공개 게시 문서 검색이다. 비공개 테스트·관리자 자료는 확장 옵션에서 기존 서버 관리자 비밀번호로 별도 연결하며 웹 인증을 자동으로 가져오지 않는다. 관리자 연결 추가 과정에서 백엔드·모델·최소 근거 프롬프트·검색·임베딩·리랭커는 변경하지 않았다. 현재 `/chat`은 이력을 수용하지만 문서 검색·생성에는 마지막 질문만 사용한다.
- offscreen의 단일 진행 요청·유한 대기(연결 설정 1~1800초, 없으면 90초)·중단·지연 응답 폐기를 문서 모드에도 적용했다. **문서 `/chat` 서버에는 화면 상담과 같은 총기한·연결 취소가 없으며 클라이언트 취소 후에도 계산이 남을 수 있다.** 비교 시 이전 서버 처리가 끝난 뒤 다음 요청을 보낸다.
- **Terra 집중 모형 검사 42개 통과:** 신규 모드 10개와 기존 stale 23·offscreen 4·timeout 5개다. 요청 경로·본문·인증 분리, 문서 흐름 DOM/캡처 호출 0, 이력·초기화 분리, 숫자·근거 안전 표시, 전환 후 오래된 응답·포트 폐기, 유한 대기·별도 포트 중복 차단→취소→새 요청, 화면 안내 유지가 확인됐다. 이 42개는 모형 검사이며 실제 Chrome 재로드·모드 전환·인증 확인 범위는 위 항목을 따른다. 실제 RAG 생성 답변·모델 평가는 수행하지 않았다.
- 브랜치 `codex/feat-floating-ui`, 이번 문서 모드 작업의 기준 커밋은 **`c3bca11`**다. 신규 모드 구현·검증·문서 변경은 같은 브랜치의 미커밋 변경이다. 원격 반영 여부는 `git status -sb`와 원격 커밋으로 확인한다. 이 인계 파일은 향후 main 배포 PR에서 제외한다.
- **A 완료:** 표시/지우기·본문 스크롤·팝업 변경 시 해제는 사용자 확인 완료. **B 실제 Chrome 완료:** 기존 검색 일치에 더해 명시적 설명 전용 0대상, 모호한 질문의 추가질문 0대상, 서로 다른 두 실제 버튼과 ① 파랑/② 주황 테두리·번호·이름의 시각 일치를 확인했다. 완료한 검사는 반복하지 않는다.
- 실제 모델이 ‘표시 없이 설명만’ 요청에도 대상을 붙이던 문제를 수정했다. 해당 명시적 의도는 생성 스키마와 후검증에서 대상 0개로 제한하며 답변 내용은 실제 Qwen이 생성한다. 일반적인 기능 질문의 대상 1개는 계약 위반으로 취급하지 않는다. 현재 Qwen1.5B의 설명은 일반적이거나 기능 의미가 부정확해 품질 한계가 있다.
- 기존 `/api/v1/desktop/guide`의 `source=dom`에서 공개 제목·문맥·라벨·후보 ID를 제한해 수집한다. 응답은 설명/추가질문/대상 0~3개다. 화면 버전·실제 ID·가시성·모달·이름을 재검증하며 이전 UIA 단일 대상 계약도 보존한다. 제품 자동 클릭·입력·스크롤·제출은 없다.
- 긴 요청은 offscreen 문서가 한 번에 하나만 수행한다. 서버와 확장은 `OLLAMA_TIMEOUT`을 올림 후 1~1800초로 제한한 예산을 공유하고 준비/캡처도 포함한다. 기존 3필드 연결 파일/시간 필드 없는 요청만 90초 호환값을 쓴다. 기한 504, 연결 종료 취소 499를 구분하며 끊긴 클라이언트에는 499 응답이 전달되지 않을 수 있다. 자동 재시도하지 않는다.
- 취소 후 서버가 최대 기한까지 잠금을 유지하던 문제와 캡처 후 창 포커스를 재검사하지 않던 문제를 수정했다. 전체 `BackEnd.main.app` 미들웨어를 포함한 격리 실제 TCP에서 단절→모형 Ollama 스트림 종료→잠금 해제→새 요청 200을 확인했다. 실제 Chrome에서도 요청 취소→제출 활성→수동 추가질문 성공(429 없음)을 확인했다. 실제 Ollama 엔진 내부 계산의 즉시 중단은 입증하지 않았다.
- **C 실제 경로 완료:** 현재 탭 아이콘으로 activeTab을 허용하고 공개 복지서비스 본문에서 전송 없는 캡처 검사가 성공했다. 실제 확장 PNG를 기존 서버에 한 번 전달해 **409 한 건 + 이미지 꺼짐 UI**를 확인했다. PNG 검증은 이미지 옵션 검사보다 먼저 수행되므로 형식/크기 검증 통과 근거다. 서버는 이미지 off였고 VLM을 호출하지 않았다.
- 입력/선택 영역과 경계가 확실한 iframe/object/embed/canvas/video를 검게 가린다. 가림이 있으면 기존 `partial`을 전달한다. 모달·열린 combobox·닫힌 커스텀 Shadow DOM은 계속 거절한다. 마스크는 합계 60개 이내이며 캡처 전후 노드·가림 좌표, 탭·URL·DOM·스크롤·뷰포트 일치를 검사한다. PNG 한 장, 최대 1280×800·원본 1.5MiB/base64 2MiB다.
- 실제 공개 Chrome의 불투명 영역 위 검은 마스크 프레임을 관측했다. 입력란 각각의 픽셀까지 시각 판정한 것은 아니며 입력값 미열람·마스크 좌표/배율·이동/새 영역/제거 시 거절은 자동 검사로 확인했다. 홈의 실제 화면 변경 거절도 확인했다. 모든 진단 이미지와 임시 이미지 허용 JSON을 삭제하고 정상 이미지 off 설정을 재불러왔다.
- 실제 확장 관리 화면의 **서비스 워커 비활성**을 관측한 뒤 추가질문 0대상 응답으로 통신 복구를 확인했다. offscreen 검사뷰 자체는 펼쳐 확인하지 않았으므로 기존 문서 재사용 여부는 대역 검사 근거와 구분한다.
- Terra 검사 통과: 초기 75개, 시간/취소 관련 서버 23개·확장 timeout 5개, 추가 독립 23개, 명시 설명 전용 4개, 마스킹 관련 22개, 마스크 이동 관련 DOM 16개. 서로 겹치는 실행이 있어 전체 고유 검사 수로 합산하지 않는다. 토큰 없음/불일치 401, 전달 헤더 403, 합성 PNG+이미지 off 409, 본문 초과 413, bounded vision 계약, deadline 없는 RAG 텍스트 경로도 확인했다.
- `BackEnd/desktop_connection.py`가 실제 토큰·이미지 옵션·`timeoutSeconds`를 비공개 JSON으로 내보내고 `Extension/start-local.ps1`도 이를 사용한다. JSON은 Git·Docker context에서 제외하고 토큰은 확장 `storage.session`에만 둔다. 이미지 체크는 첨부 여부이며 모델 선택이 아니다. 서버 `OLLAMA_LLM`은 RAG와 화면 상담에 공통 적용된다.
- 화면 상담 A/B/C 검증 당시 설정은 `qwen2.5:1.5b-instruct`, 문맥 16384, timeout 600초, 상담 on, 이미지 off, loopback이었다. 당시 백엔드만 갱신하고 Ollama·문서 워커를 보존했으며 실제 UI의 이미지 꺼짐/600초와 Qwen의 vision 미지원을 확인했다. 그 검증에서는 모델 다운로드·VLM 추론·DB 쓰기를 하지 않았다. 이후의 MD 적재·백엔드/워커 갱신은 이 절 맨 앞의 최신 항목을 따른다.
- Linux 실행 이미지의 모듈/경로/설정과 네트워크 없는 `ssh -G`의 포워딩/실패 종료 옵션을 확인했다. Windows 8000은 로컬 Docker가 점유 중이므로 현재 그대로 원격 터널을 열 수 없다. 실제 EC2 SSH 터널 연결은 검사하지 않았다.

- 최종 코드 검토의 두 경계를 수정했다. 이전 포트의 지연 disconnect/응답은 현재 요청 버전·포트 소유권·완료 상태를 먼저 확인해 새 요청 타이머와 UI를 변경하지 않는다. 문서와 열린 Shadow DOM은 같은 속성 필터를 사용해 aria-label/aria-labelledby/title/id/for와 role/href/type 변경을 관측한다.
- 후보의 계산된 이름·역할/입력 유형·해석된 링크 목적지가 달라지면 표시와 현재 지시를 함께 정리한다. 링크 목적지와 의미 서명은 확장 메모리에만 보관하며 API payload에 넣지 않는다. 의미가 같은 상대/절대 URL, 이름 원천이 아닌 title 등과 무관한 노드 속성 변경은 기존 안내를 유지한다.
- 이 두 수정의 **Terra 직접 영향 검사 44개 통과**: 실제 지연 disconnect→새 요청 기한/사용자 취소 유지, 이름·href/role/type 변경, 열린 Shadow DOM, 무관/동일 의미 변경 유지, payload 비노출을 확인했다. 해당 검사에서는 기존 Chrome A/B/C·캡처·모델 검사를 반복하지 않았다. 이후 문서 모드·관리자 연결 검증에서 최신 확장과 공개 GET 탭을 다시 불러왔으며 실제 확인 범위는 이 절 맨 앞을 따른다.

## 할일

- 신규 문서 모드·관리자 연결은 로컬 구현이며 커밋·push하지 않았다. 실제 Chrome의 모드 선택·인증 상태는 확인했고, 실제 생성 답변·근거 표시와 장기 비교는 미검증이다. 새 MD의 관리자 검색은 위 범위에서 확인했지만 PDF 파싱·생성 답변 품질 비교는 하지 않았다. 확장 재로드 시 공개 GET 진입 탭도 다시 열고 정상 연결 JSON·관리자 세션을 다시 연결한다. 별도 answer-key는 설계 담당 범위이며 적재하지 않는다.
- 설계 세션의 이전 포트 타이머·이름/역할/링크 변경 검토는 완료됐다. 최신 JS의 실제 Chrome 재로드도 수행했으며 문서 모드 전환·인증·강조 해제는 확인했다. 이전 모델 질의와 A/B/C 전체를 반복한 것은 아니므로 실제 검증 범위는 한일의 항목별 근거와 구분한다.
- 실제 입력란 각각의 마스크 픽셀, 실제 600초 장기 대기, Spot 실제 단절, 실제 Ollama 엔진 즉시 중단은 미확인이다. 각각 자동 좌표/가짜 시계/연결 실패 대역/HTTP 스트림 정리 검사와 구분한다. Qwen1.5B의 기능 설명 품질은 별도 한계다.
- EC2는 아직 접속·조회·전송·다운로드·배포·추론하지 않았다. 기동 요청 후 실제 GPU 적재·Ollama 버전/vision capability·네트워크/SSH 터널·디스크·새 모델 호환을 확인한다. g4dn.2xlarge의 준비·다운로드·비교·복귀 전체를 30분 이내로 제한하며, VLM은 실제 여유 자원과 다운로드 시간을 보고 선택한다. 기존 LLM과 같은 크기는 필수 조건이 아니며 임베딩·리랭커는 유지한다.
- 최초 런타임 환경 주입 이후 갱신은 `git pull --ff-only`, `docker compose up -d --build`로 준비했다. **로컬 코드가 승인 후 원격에 게시되기 전에는 pull로 받을 수 없다.** 공개 경로 차단·포트 충돌 처리·비공개 JSON·순차 비교·기준 모델 복귀는 README를 따른다.

## 사용자 추가지침

- 자체 테스트는 **기존 Terra 하위 에이전트**가 담당한다. 사용자가 열어둔 일반 Chrome의 공식 복지로 탭을 PowerShell UIA·Win32로 확인한다. Codex 인앱브라우저·새 Chrome 프로필·재설치는 요청 범위가 아니다. UIA 누락과 실제 정책 거절을 구분하고 허용된 현재 화면 관측으로 상태를 확인한다.
- 현재 진행한 로컬 추가 검토·수정·검증에는 별도 승인이 필요 없다. 실제 도구의 정책 거절은 우회하지 않는다. URL·전면 창·좌표를 새로 확인하고 다른 창, 특히 VSCode의 .env를 읽지 않는다. 스크린샷은 필요한 검증에만 사용하고 즉시 정리한다.
- 하위 화면 새로고침에서 **양식 다시 제출** 창이 뜨면 재제출하지 말고 취소한 뒤 공식 공개 GET 진입 주소로 돌아간다. 사용자 인증·신청 제출·개인정보 입력을 하지 않는다.
- 추가 커밋·push·PR·main 변경, worktree, .env 직접 열람/편집, 키 출력, Vercel 변경은 하지 않는다. 이번 기존 목업 검색 자료 교체·새 가상 MD 적재 범위에서는 테이블 구조를 유지한 기존 내용 초기화가 허용돼 완료했다. 스키마·트리거·Auth·관리자·부서 등 무관한 변경은 계속 금지한다. 런타임 자격정보는 출력 없이 기존 인증·DB 연결에만 사용하고 설정 예시는 `.env.example`을 쓴다.
- 지금 EC2에 접근하거나 새 모델을 다운로드하지 않는다. 사용자 기동+테스트 요청 뒤에만 D/E를 진행한다. 이미지 옵션 on을 모델 교체로 해석하지 않는다.
- Chrome·앱·서버·문서 워커·데이터·캐시를 테스트하기 쉽게 켜 둔다. 본인이 만든 검사용 요청·터널·측정 프로세스만 정리하고 factory reset·캐시/데이터 삭제는 하지 않는다.
