# 확장 화면 상담 인계

현재 제품 경로는 `Extension/`의 unpacked MV3 Chrome 확장이다. Desktop/Electron 앱·제품용 UIA 수집기는 실행하지 않는다. 실제 UI 테스트 도구는 기존 일반 Chrome을 조작하는 PowerShell UIA·Win32다. 실행·EC2 전환 절차는 [확장 README](../Extension/README.md)를 따른다.

## 한일

- 브랜치 `codex/feat-floating-ui`, 기본 구현의 기준 커밋은 **`1f3ea7e`**다. 이후 안정화 수정·검증·문서 변경도 같은 브랜치에서 이어진다. 원격 반영 여부는 `git status -sb`와 원격 커밋으로 확인한다. 이 인계 파일은 향후 main 배포 PR에서 제외한다.
- **A 완료:** 표시/지우기·본문 스크롤·팝업 변경 시 해제는 사용자 확인 완료. **B 실제 Chrome 완료:** 기존 검색 일치에 더해 명시적 설명 전용 0대상, 모호한 질문의 추가질문 0대상, 서로 다른 두 실제 버튼과 ① 파랑/② 주황 테두리·번호·이름의 시각 일치를 확인했다. 완료한 검사는 반복하지 않는다.
- 실제 모델이 ‘표시 없이 설명만’ 요청에도 대상을 붙이던 문제를 수정했다. 해당 명시적 의도는 생성 스키마와 후검증에서 대상 0개로 제한하며 답변 내용은 실제 Qwen이 생성한다. 일반적인 기능 질문의 대상 1개는 계약 위반으로 취급하지 않는다. 현재 Qwen1.5B의 설명은 일반적이거나 기능 의미가 부정확해 품질 한계가 있다.
- 기존 `/api/v1/desktop/guide`의 `source=dom`에서 공개 제목·문맥·라벨·후보 ID를 제한해 수집한다. 응답은 설명/추가질문/대상 0~3개다. 화면 버전·실제 ID·가시성·모달·이름을 재검증하며 이전 UIA 단일 대상 계약도 보존한다. 제품 자동 클릭·입력·스크롤·제출은 없다.
- 긴 요청은 offscreen 문서가 한 번에 하나만 수행한다. 서버와 확장은 `OLLAMA_TIMEOUT`을 올림 후 1~1800초로 제한한 예산을 공유하고 준비/캡처도 포함한다. 기존 3필드 연결 파일/시간 필드 없는 요청만 90초 호환값을 쓴다. 기한 504, 연결 종료 취소 499를 구분하며 끊긴 클라이언트에는 499 응답이 전달되지 않을 수 있다. 자동 재시도하지 않는다.
- 취소 후 서버가 최대 기한까지 잠금을 유지하던 문제와 캡처 후 창 포커스를 재검사하지 않던 문제를 수정했다. 전체 `BackEnd.main.app` 미들웨어를 포함한 격리 실제 TCP에서 단절→모형 Ollama 스트림 종료→잠금 해제→새 요청 200을 확인했다. 실제 Chrome에서도 요청 취소→제출 활성→수동 추가질문 성공(429 없음)을 확인했다. 실제 Ollama 엔진 내부 계산의 즉시 중단은 입증하지 않았다.
- **C 실제 경로 완료:** 현재 탭 아이콘으로 activeTab을 허용하고 공개 복지서비스 본문에서 전송 없는 캡처 검사가 성공했다. 실제 확장 PNG를 기존 서버에 한 번 전달해 **409 한 건 + 이미지 꺼짐 UI**를 확인했다. PNG 검증은 이미지 옵션 검사보다 먼저 수행되므로 형식/크기 검증 통과 근거다. 서버는 이미지 off였고 VLM을 호출하지 않았다.
- 입력/선택 영역과 경계가 확실한 iframe/object/embed/canvas/video를 검게 가린다. 가림이 있으면 기존 `partial`을 전달한다. 모달·열린 combobox·닫힌 커스텀 Shadow DOM은 계속 거절한다. 마스크는 합계 60개 이내이며 캡처 전후 노드·가림 좌표, 탭·URL·DOM·스크롤·뷰포트 일치를 검사한다. PNG 한 장, 최대 1280×800·원본 1.5MiB/base64 2MiB다.
- 실제 공개 Chrome의 불투명 영역 위 검은 마스크 프레임을 관측했다. 입력란 각각의 픽셀까지 시각 판정한 것은 아니며 입력값 미열람·마스크 좌표/배율·이동/새 영역/제거 시 거절은 자동 검사로 확인했다. 홈의 실제 화면 변경 거절도 확인했다. 모든 진단 이미지와 임시 이미지 허용 JSON을 삭제하고 정상 이미지 off 설정을 재불러왔다.
- 실제 확장 관리 화면의 **서비스 워커 비활성**을 관측한 뒤 추가질문 0대상 응답으로 통신 복구를 확인했다. offscreen 검사뷰 자체는 펼쳐 확인하지 않았으므로 기존 문서 재사용 여부는 대역 검사 근거와 구분한다.
- Terra 검사 통과: 초기 75개, 시간/취소 관련 서버 23개·확장 timeout 5개, 추가 독립 23개, 명시 설명 전용 4개, 마스킹 관련 22개, 마스크 이동 관련 DOM 16개. 서로 겹치는 실행이 있어 전체 고유 검사 수로 합산하지 않는다. 토큰 없음/불일치 401, 전달 헤더 403, 합성 PNG+이미지 off 409, 본문 초과 413, bounded vision 계약, deadline 없는 RAG 텍스트 경로도 확인했다.
- `BackEnd/desktop_connection.py`가 실제 토큰·이미지 옵션·`timeoutSeconds`를 비공개 JSON으로 내보내고 `Extension/start-local.ps1`도 이를 사용한다. JSON은 Git·Docker context에서 제외하고 토큰은 확장 `storage.session`에만 둔다. 이미지 체크는 첨부 여부이며 모델 선택이 아니다. 서버 `OLLAMA_LLM`은 RAG와 화면 상담에 공통 적용된다.
- 현재 설정: `qwen2.5:1.5b-instruct`, 문맥 16384, timeout 600초, 상담 on, 이미지 off, loopback. 백엔드만 갱신했고 기존 Ollama·문서 워커를 보존했다. 실제 UI에서도 이미지 꺼짐/600초 정상 설정을 확인했다. Qwen 메타데이터는 vision 미지원이다. 모델 다운로드·VLM 추론·DB 쓰기는 하지 않았다.
- Linux 실행 이미지의 모듈/경로/설정과 네트워크 없는 `ssh -G`의 포워딩/실패 종료 옵션을 확인했다. Windows 8000은 로컬 Docker가 점유 중이므로 현재 그대로 원격 터널을 열 수 없다. 실제 EC2 SSH 터널 연결은 검사하지 않았다.

- 최종 코드 검토의 두 경계를 수정했다. 이전 포트의 지연 disconnect/응답은 현재 요청 버전·포트 소유권·완료 상태를 먼저 확인해 새 요청 타이머와 UI를 변경하지 않는다. 문서와 열린 Shadow DOM은 같은 속성 필터를 사용해 aria-label/aria-labelledby/title/id/for와 role/href/type 변경을 관측한다.
- 후보의 계산된 이름·역할/입력 유형·해석된 링크 목적지가 달라지면 표시와 현재 지시를 함께 정리한다. 링크 목적지와 의미 서명은 확장 메모리에만 보관하며 API payload에 넣지 않는다. 의미가 같은 상대/절대 URL, 이름 원천이 아닌 title 등과 무관한 노드 속성 변경은 기존 안내를 유지한다.
- 이 두 수정의 **Terra 직접 영향 검사 44개 통과**: 실제 지연 disconnect→새 요청 기한/사용자 취소 유지, 이름·href/role/type 변경, 열린 Shadow DOM, 무관/동일 의미 변경 유지, payload 비노출을 확인했다. 기존 Chrome A/B/C·캡처·모델 검사는 반복하지 않았고 브라우저·서비스·설정도 변경하지 않았다. 새 JS 수정은 소스에만 있으며 현재 Chrome에 적용하려면 확장과 공개 GET 진입 탭을 새로고침하고 연결 파일을 다시 불러와야 한다.

## 할일

- 설계 세션에서 두 수정분과 집중 회귀 코드를 재검토했다. 이전 포트의 타이머 접근 차단과 이름·역할·링크 변경 시 표시 정리를 확인했으며, 이 검토 범위에서 추가 수정은 필요하지 않다. 최신 JS의 실제 Chrome 재로드·재검증은 아직 수행하지 않았으므로 기존 실제 화면 검증과 구분한다.
- 실제 입력란 각각의 마스크 픽셀, 실제 600초 장기 대기, Spot 실제 단절, 실제 Ollama 엔진 즉시 중단은 미확인이다. 각각 자동 좌표/가짜 시계/연결 실패 대역/HTTP 스트림 정리 검사와 구분한다. Qwen1.5B의 기능 설명 품질은 별도 한계다.
- EC2는 아직 접속·조회·전송·다운로드·배포·추론하지 않았다. 기동 요청 후 실제 GPU 적재·Ollama 버전/vision capability·네트워크/SSH 터널·디스크·새 모델 호환을 확인해야 하므로 모델 성능 비교만 남았다고 주장하지 않는다. 비교 후보는 기존 30B LLM과 같은 규모의 `qwen3-vl:30b-a3b-instruct-q4_K_M`이며 아직 채택하지 않았다. 마지막 알려진 T4 약 15GiB는 전체 GPU 적재를 보장하지 않는다.
- 최초 런타임 환경 주입 이후 갱신은 `git pull --ff-only`, `docker compose up -d --build`로 준비했다. **로컬 코드가 승인 후 원격에 게시되기 전에는 pull로 받을 수 없다.** 공개 경로 차단·포트 충돌 처리·비공개 JSON·순차 비교·기준 모델 복귀는 README를 따른다.

## 사용자 추가지침

- 자체 테스트는 **기존 Terra 하위 에이전트**가 담당한다. 사용자가 열어둔 일반 Chrome의 공식 복지로 탭을 PowerShell UIA·Win32로 확인한다. Codex 인앱브라우저·새 Chrome 프로필·재설치는 요청 범위가 아니다. UIA 누락과 실제 정책 거절을 구분하고 허용된 현재 화면 관측으로 상태를 확인한다.
- 현재 진행한 로컬 추가 검토·수정·검증에는 별도 승인이 필요 없다. 실제 도구의 정책 거절은 우회하지 않는다. URL·전면 창·좌표를 새로 확인하고 다른 창, 특히 VSCode의 .env를 읽지 않는다. 스크린샷은 필요한 검증에만 사용하고 즉시 정리한다.
- 하위 화면 새로고침에서 **양식 다시 제출** 창이 뜨면 재제출하지 말고 취소한 뒤 공식 공개 GET 진입 주소로 돌아간다. 사용자 인증·신청 제출·개인정보 입력을 하지 않는다.
- 추가 커밋·push·PR·main 변경, worktree, .env 직접 열람/편집, 키 출력, DB/스키마 변경·문서/임베딩 재적재, Vercel 변경은 하지 않는다. 설정 예시는 `.env.example`을 쓰고 실제 값은 런타임에 주입한다.
- 지금 EC2에 접근하거나 새 모델을 다운로드하지 않는다. 사용자 기동+테스트 요청 뒤에만 D/E를 진행한다. 이미지 옵션 on을 모델 교체로 해석하지 않는다.
- Chrome·앱·서버·문서 워커·데이터·캐시를 테스트하기 쉽게 켜 둔다. 본인이 만든 검사용 요청·터널·측정 프로세스만 정리하고 factory reset·캐시/데이터 삭제는 하지 않는다.
