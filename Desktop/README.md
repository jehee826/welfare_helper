# 곁에 Desktop · Windows 로컬 연결

트레이 대기 → Chrome의 **정확한 HTTPS 복지로 호스트** 확인 → 패널을 포커스 탈취 없이 표시합니다.
공식 진입 주소: https://www.bokjiro.go.kr/ssis-tbu/index.do . 같은 호스트의 후속 경로도 대상입니다.

## 실행 (Windows CMD)

Node.js 22.12 이상과 Windows PowerShell/UI Automation이 필요합니다.

```cmd
cd Desktop
npm ci
npm start
```

처음 의존성 설치만 인터넷이 필요합니다. 실행 후에는 기본적으로 트레이에 있습니다.
Chrome은 사용자가 평소 쓰던 창 그대로 열며 앱은 재시작·프로필 생성·디버깅 포트·확장 설치를 하지 않습니다.
트레이에서 수동으로 열어 RAG 상담을 사용할 수도 있습니다. `×`는 숨김이며, 사용자가 숨긴 탭에서는 즉시 다시 표시하지 않습니다.
수정된 코드를 적용하려면 **트레이 메뉴 → 종료**한 뒤 `npm start`를 다시 실행하세요.

## 하나의 Ollama 생성 모델, 두 모드

| 모드 | 요청 경로 | 입력 |
|---|---|---|
| RAG 상담 | 로컬 FastAPI `/api/v1/chat` | 기존 문서 질문 계약, 기존 검색·근거·프롬프트 유지 |
| 화면 안내 | 로컬 FastAPI `/api/v1/desktop/guide` | 사용자 목표 + 공개 접근성 후보 + 짧은 진행 |

두 모드는 **같은 로컬 Ollama 컨테이너와 서버의 `OLLAMA_LLM` 하나**를 사용합니다. 프롬프트와 메모리 이력은 별도이며 디스크에 대화를 저장하지 않습니다.
Desktop에는 별도 생성 모델 설정이 없습니다. 기본 API는 `http://127.0.0.1:8000`이며 EC2 자동 우회는 없습니다.
서버가 없거나 화면 안내가 비활성이면 연결/설정 안내를 표시합니다. 고정 응답으로 대신하지 않습니다.

사용자가 관리하는 **로컬 루트 환경 설정**에서 다음을 맞춥니다. EC2·운영 설정은 변경할 필요가 없습니다.

```dotenv
OLLAMA_LLM=qwen2.5:1.5b-instruct
OLLAMA_RUNTIME=runc
LLM_NUM_THREAD=2
OLLAMA_TIMEOUT=600
DESKTOP_GUIDANCE_ENABLED=true
```

`bge-m3`·1024차원·리랭커·DB 연결 등 기존 RAG 설정은 유지합니다. 같은 서버의 두 모드에 공통 생성 모델을 적용합니다.
백엔드 변경 및 환경 설정 반영이 필요하면 사용자가 저장소 루트에서 실행합니다.

```cmd
docker compose up -d --build
```

처음 필요한 모델이 없으면 기존 Compose 준비 과정에서 다운로드될 수 있습니다. 이미 설치된 1.5B를 쓰려면 `docker compose exec ollama ollama list`로 확인하세요.
Ollama의 `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_LOADED_MODELS=1` 설정을 유지하며 추가 컨테이너를 만들지 않습니다.
화면 안내는 Desktop에서 실행 요청 1개·최신 대기 1개로 제한하고, 서버도 안내 요청 하나만 허용합니다.
**RAG까지 포함한 애플리케이션 전역 대기열은 없습니다.** 공용 Ollama가 자체 직렬 처리합니다. Desktop 취소 후에도 서버의 기존 생성이 끝날 때까지 새 안내가 거부될 수 있습니다.

Desktop 전용 주소를 바꿀 필요가 있을 때만 같은 CMD에서 설정합니다. 기본값이면 생략합니다.

```cmd
set DESKTOP_API_BASE_URL=http://127.0.0.1:8000
npm start
```

허용 주소는 HTTP `127.0.0.1`/`localhost`의 8000 포트뿐입니다. `.env`는 앱에서 자동 로딩하지 않습니다([예시](.env.example)). 키·관리자 비밀번호를 앱에 넣지 않습니다.

## 화면 안내 확인

1. 기존 Chrome에서 복지로를 열고 패널이 나타나는지 확인합니다. 주소창·선택 탭을 UIA로 검증하지 못하면 트레이 대기를 유지합니다.
2. **화면 안내**에서 개인정보 없는 목표를 입력합니다. 공개 목록에 있는 버튼/링크/메뉴만 후보로 전달합니다.
3. 실제 후보 ID가 있는 구조화 응답만 안내합니다. JSON 불완전·가짜 ID·요소 미확인·서버 실패는 보류합니다.
4. 패널 사용 중에는 브라우저 연결을 유지하지만 강조는 멈춥니다. 브라우저가 다시 활성이고 해당 요소가 표시·활성·가림 검사까지 통과하면 강조합니다.
5. 사용자가 직접 조작한 뒤 **화면 변화 확인**을 누릅니다. 실제 요소 변화와 예상 라벨을 대조하며 클릭만으로 완료 처리하지 않습니다.
6. 다른 사이트·앱·탭으로 전환하면 진행 중 요청을 무효화하고 강조를 중지합니다. 스크롤·좌표 갱신 자체는 모델을 호출하지 않습니다.

실제 화면은 UIA 주기적 스냅샷 기준이므로 감지에 지연이 있습니다. 정보가 오래되면 강조를 숨깁니다.
UIA 좌표는 물리 픽셀에서 Electron DIP로 변환하며, 한 디스플레이 안에 완전히 포함되는 요소만 강조합니다.
가림 검사는 UIA 5개 지점과 패널 사각형 기준이며 모든 OS 레이어를 완벽히 판별하지 않습니다. 다중 배율·다중 모니터는 실제 환경 확인이 필요합니다.
화면 밖 요소는 UIA만으로 스크롤 방향을 확신할 수 없으면 방향을 안내하지 않습니다.

## 개인정보와 수집 한계

- 주소창의 URL은 정확한 scheme/host/포트 확인에만 사용하고 원문 URL·쿼리는 전송/로그하지 않습니다. 탐색 식별은 일회성 소금값을 적용한 메모리 해시로 구분합니다.
- 입력칸·암호·인증코드·주민번호·쿠키·페이지 본문·이미지는 모델 입력에 포함하지 않습니다. 후보 라벨은 `shared/public-labels.json`의 제한된 공개 목록으로 필터링합니다.
- 목록에 없는 제도명이나 버튼, 접근성 미노출 화면은 안내하지 못할 수 있습니다. 브라우저 UI 영역의 주소창·선택 탭을 검증하지 못한 Chrome 구성은 보류합니다.
- UIA 읽기는 활성 Chrome 또는 사용자 패널에 연결된 검증 대상에 수행합니다. 시작·수동 열기에서는 최대 6개 Chrome 최상위 창의 선택 탭을 읽어 복지로 대상 하나를 찾습니다. 여러 개면 사용자가 원하는 창을 활성화해야 합니다. 백그라운드 대상은 활성이라고 간주하지 않습니다. 자동 클릭·스크롤·입력·제출 및 화면 캡처/VLM은 없습니다.
- 로컬 모델에 보낼 목표에도 개인 식별값을 넣지 마세요. 서버 화면 안내는 기본 비활성이며 로컬에서만 켜세요.

## 개발용 시연과 검증

**개발 시연** 모드는 기존 가상 창과 고정 응답입니다. 실제 UIA·RAG 연결을 대체하지 않습니다. 이 모드에서는 Chrome 감시를 중단합니다.
실행 중인 사용자 앱은 그대로 두고 순수 경계 검증 및 빌드만 할 수 있습니다.

```cmd
npm run test:assistant
npm run build
```

`npm run test:geometry`는 이전 연습 화면의 좌표 검사, `npm run smoke`는 별도 네이티브 시연 검사입니다. 앱 실행 중에는 중복 실행하지 마세요.
`npm run pack`은 `release/Gyeote-win32-<아키텍처>/Gyeote.exe` 포터블 폴더를 만듭니다. 폴더 전체가 필요하며 설치 마법사·자동 업데이트·부팅 자동 실행은 미구현입니다.

## Chrome 감지 진단 (모델·클릭·화면 캡처 없음)

저장소 루트의 Windows CMD에서 다음 명령은 Chrome 창 수, 주소창·문서·선택 탭 수, URL 검증 결과, 읽기 시간만 출력합니다. 창 제목·전체 URL·입력값·페이지 본문을 출력하지 않습니다.

```cmd
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File Desktop/native/watch.ps1 -Diagnose
```

- `verified`: 해당 창의 현재 선택 탭을 복지로 HTTPS 주소로 검증했습니다.
- `url_not_target`: 진단 당시 선택 탭의 주소가 허용 URL로 검증되지 않았습니다. 복지로가 다른 탭에 열려 있을 가능성과 구분하세요.
- `url_scheme_missing`: 주소창이 scheme을 생략해 HTTPS 여부를 확증하지 못했습니다. HTTP로 추측하거나 제목으로 우회하지 않습니다.
- `addressbar_missing` / `selected_tab_unverified` / `no_accessibility_document`: 주소창·선택 탭·문서 중 어느 부분이 미확인인지 구분합니다.
- `chrome_not_found` / `target_not_selected` / `ambiguous_target`: Chrome 창 없음, 미선택, 복수 대상입니다. 원하는 일반 Chrome 복지로 탭을 직접 선택하거나 트레이에서 다시 여세요.

다른 앱으로 옮겨도 마지막 Chrome handle은 보존하지만 **사용할 때마다 프로세스·주소·선택 탭을 재검증**합니다. 패널 클릭을 Chrome 비활성 전환과 분리하고, 트레이 재열기는 재탐색을 요청합니다.
주소창 탐색은 웹 Document 하위로 내려가지 않는 브라우저 UI 트리 1회 순회로 제한합니다. Document가 없어도 주소 검증 자체를 먼저 수행합니다.
활성 창 변화는 100ms 간격으로 따로 감지해 강조를 중단합니다. 페이지 읽기는 400ms 대기 + 실제 UIA 소요 시간이 있으므로 탭/내용 변경에는 지연이 있을 수 있습니다.
UIA 읽기가 멎으면 **3.5초** 뒤 강조를 숨기고, **20초** 무응답이면 앱 소유 읽기 프로세스만 중단합니다. 포커스 알림이 와도 이 watchdog을 연장하지 않습니다.

이번 버그의 집중 회귀검사는 `npm run test:tracking`으로 실행합니다. 관리자 실행이나 Chrome 플래그 변경을 일괄 해결책으로 요구하지 않습니다.
