# 곁에 Chrome 확장

개발자 모드의 압축해제된 MV3 확장이다. 공식 복지로에서만 실행하며 실제 클릭은 사용자가 한다.

기본 생성 모델은 기존 EC2 LLM `qwen3:30b-a3b-instruct-2507-q4_K_M`을 유지한다. 로컬 경량 확인은 Qwen2.5 1.5B를 사용한다. VLM은 향후 선택적 비교 경로다. 설계와 로컬 평가·인계 위치는 [문서 목차](../docs/README.md)를 따른다.

1. Chrome의 `chrome://extensions`에서 **개발자 모드**를 켠다.
2. **압축해제된 확장 프로그램을 로드합니다**에서 이 `Extension` 폴더를 선택한다.
3. 기존 일반 Chrome에서 https://www.bokjiro.go.kr/ssis-tbu/index.do 를 연다. 하위 화면의 새로고침에서 **양식 다시 제출** 창이 뜨면 취소하고 이 공개 진입 주소로 돌아간다.
4. **복지 상담**은 등록 문서를 검색하며 화면을 수집하지 않는다. **화면 안내**는 현재 공개 화면의 제목·문구·요소 이름으로 설명한다.
5. 화면 질문에 필요한 요소는 최대 3개까지 색·번호로 표시한다. 범례에는 현재 요소의 이름과 종류를 표시하며, **표시 지우기**로 해제한다. 대상이 바뀌거나 화면 밖으로 나가면 표시를 지운다.

## 화면 질문 실행

Docker Desktop이 정상일 때 저장소 루트 CMD에서 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Extension\start-local.ps1`을 실행한다. 기존 Qwen1.5B/bge-m3 캐시만 사용하며 새 모델을 다운로드하지 않는다.

서버가 준비되면 확장과 복지로 공개 진입 탭을 새로고침하고, 패널의 **연결 설정**에서 `.local\extension-connection.json`을 불러온다. 토큰은 채팅/Git에 보내지 않으며 브라우저를 닫으면 확장 세션에서 지워진다. 질문에 따라 설명만 하거나 실제 요소 0~3개를 표시한다. ‘표시 없이 설명만’ 요청은 대상 0개로 제한한다.

패널의 **문서 관리**는 기존 관리자 웹을 새 탭으로 연다. 웹에서 서버 공통 비밀번호로 로그인해 원문을 등록·교체하며, 확장 세션·내 정보·상담은 주소에 전달하지 않는다. 서버 연결 파일을 불러오는 **연결 설정**과는 별개다.

이미지는 기본 off다. **이미지 체크는 화면 첨부 여부이며 모델 선택이 아니다.** 서버의 `OLLAMA_LLM`이 일반 RAG와 화면 상담에 공통 적용된다. 첨부하려면 확장 아이콘으로 현재 탭 캡처 권한을 부여하고, 공개 화면의 전송 안내를 확인한 뒤 질문한다.

패널은 헤더로 이동하고 접기·닫기·다시 열기를 지원한다. 닫으면 열기 버튼으로, 다시 열거나 펼치면 질문 입력 또는 첫 이용 폼으로 포커스를 옮긴다. 작은 창에서는 패널 안을 세로로 스크롤할 수 있다. 개발용 강제 표시·이미지 검사 버튼은 일반 패널에서 제공하지 않는다.

제품 실행에는 Desktop/Electron 앱이나 UIA 수집기가 필요 없다. 다른 사이트, 로그인·인증·개인정보 화면과 닫힌 Shadow DOM은 시연 범위 밖이다. 입력란과 프레임·캔버스·영상 영역은 검게 가리고 나머지 공개 영역만 보낸다. 가림이 있으면 부분 화면으로 전달하며, 모달·열린 선택 목록·닫힌 Shadow DOM은 캡처를 거절한다. 탭·스크롤·화면 크기·마스크 위치가 캡처 중 바뀌어도 전송하지 않는다.

DOM 안전성 검사는 기존 프론트엔드의 개발 의존성 `jsdom`을 사용한다. 저장소 루트에서 `node --test Extension/tests/dom.test.cjs`로 실행한다. 이 검사는 실제 Chrome 설치·표시 검증을 대신하지 않는다.

## 문서 질문 (RAG)

추천 질문은 최대 3개이며 누르면 **초안만 입력**한다. 기존 초안은 덮어쓰지 않는다. 음성 인식을 지원하는 브라우저에서는 **음성 입력**을 눌러 최대 30초간 한국어를 듣고, 결과를 확인·수정한 뒤 직접 전송한다. 음성은 브라우저의 외부 인식 서비스로 전송될 수 있으므로 민감정보는 말하지 않는다. 취소·직접 입력·상담/모드 전환·패널 닫기·탭 숨김은 인식을 중단하며, 권한 거부나 미지원 환경에서도 텍스트 입력을 사용할 수 있다.

기본 **복지 상담**에서 첫 이용 시 선택 조건을 입력하거나 **나중에 입력**을 선택한다. 나이·가구·지역·장애 여부의 모름은 빈 값, 소득 모름은 `unknown`으로 보관한다. **내 정보 수정 / 내 정보 삭제**로 변경하며, 같은 브라우저를 공유하면 정보도 공유될 수 있다. 조건은 worker가 확장 전용 `chrome.storage.local`에 저장하고 신뢰 컨텍스트로 접근을 제한한다. 확장 삭제·저장소 삭제 후에는 복구되지 않는다. [Chrome 저장소 설명](https://developer.chrome.com/docs/extensions/reference/api/storage)

공개 상담은 **이전 상담**에서 목록·상세를 열고 계속 질문한다. 마지막 선택 상담은 새로고침·재방문 때 복원한다. **새 상담**은 기존 기록을 보존하며, 개별·전체 삭제는 대상 확인 후 실행하고 내 정보는 유지한다. 관리자 문서 상담과 화면 안내는 영구 저장하지 않는다.

한도는 **30상담·상담당 100메시지(50쌍)·UTF-8 4MiB**다. 성공한 질문·답변을 한 쌍으로 저장하고, 실패·취소 응답은 저장하지 않는다. 공간 부족 시 과거 기록을 자동 삭제하지 않는다. **저장되지 않은 답변**을 유지하고, 정리 후 같은 상담에 재저장하거나 명시적으로 선택한 상담에 보관할 수 있다. 이 동작은 모델을 다시 호출하지 않는다. 다른 탭 충돌·손상은 안내하고, 손상 저장소의 명시 재설정은 프로필·연결 설정을 건드리지 않는다.

대화는 확장 전용 로컬 저장소에 개인정보 형식을 가려 보관한다. DOM·HTML·이미지·인증정보·원문 context는 저장하지 않는다. 근거는 답변당 최대 10건, 인용당 1000자, URL 2048자, 쪽·블록 각각 50개 참조까지만 보관하며 축약 여부를 표시한다. 저장한 근거는 당시 자료이며 현재 유효성을 재검증한 결과가 아니다. 개인정보 자동 가림이 모든 민감정보를 판별하지는 못하므로 질문에 직접 입력하지 않는다.

**질문 모드**에서 **화면 안내**로 전환하면 진행 요청·테두리를 정리한다. 화면 안내·관리자의 **임시 대화 지우기**는 현재 모드의 메모리만 비운다. 새 코드는 확장과 공개 GET 진입 탭을 새로고침한 뒤 사용한다.

문서 모드는 `POST /api/v1/chat`에 질문(300자 이내)·현재 조건 `profile`·최근 문서 이력(최대 12개·6000자)과 선택적 `conversation_context`를 보낸다. 조건·대화는 검색 의도와 답변 맥락에 사용하며, 사실의 근거는 이번에 검색한 원문뿐이다. 현재 조건의 모름은 과거 요약으로 채우지 않으며 모순·대상 모호성은 확인이 필요하다. DOM·캡처·이미지·대상 ID는 보내지 않는다. 화면 안내에는 문서 조건·요약을 보내지 않는다. 답변 표시·저장 전 조건 revision과 접근 권한을 다시 확인한다.

공개 상담의 미요약 대화가 6쌍이면 오래된 최대 3쌍부터 요약하고, 이후 3쌍이 쌓일 때 다시 갱신한다. 요약은 최대 1200자, 갱신 batch는 연속된 최대 6메시지·6000자이며 최근 이력과 중복하지 않는다. 첫 쌍이 너무 길면 건너뛰어 요약 완료로 처리하지 않고 일부 맥락 제외를 표시한다. 요약 실패 시 기존 요약을 유지하고 batch·최근 이력에서 예산에 맞는 최근 쌍으로 답변을 계속한다. 취소·기한 초과는 요청을 중단한다.

기존 요청별 LLM으로 맥락 준비 최대 1회와 답변 최대 1회만 실행한다. 모델 입력 예산이 부족하면 오래된 이력을 쌍 단위로 제외하며, 최소 원문도 담을 수 없으면 답변을 보류한다. 요약과 현재 답변은 같은 로컬 변경으로 저장한다. 미저장 답변을 다른 상담에 보관할 때 원래 상담의 요약은 옮기지 않는다. 관리자 상담은 최근 메모리 이력만 사용한다. 이 제한된 맥락이 전체 대화를 완벽하게 기억하거나 실제 복지 정확도를 보장하지는 않는다.

과거 대화·요약은 맥락 준비에 사용하고, 최종 생성에는 해소된 검색 의도·현재 조건·현재 질문·이번 원문만 전달한다. 과거 assistant 답변과 요약 원문은 최종 사실답변 입력에서 제외하며, 준비 단계에서 대상·조건이 모호하다고 판단하면 확인 질문을 반환한다.

요약 상태 `context_update`와 맥락 일부 제외 여부 `context_usage.omitted`를 구분해 저장·표시한다. 요약 갱신에 성공해도 답변 생성에서 일부 이력이 제외될 수 있다. 입력 비용은 UTF-8 기반의 보수적 추정이며 정확한 토큰 수는 아니다.

답변과 서버의 `evidence` 원문·쪽·블록·출처를 표시한다. 선택된 인용 문구의 원문 포함·숫자/연락처 대응은 검사하지만 **검색 원문 전체가 답변의 모든 주장과 일치한다고 검증한 것은 아니다.** 표시한 근거는 실제 생성 입력에 포함한 원문 범위이며 과거 답변·요약을 새 공식 근거로 취급하지 않는다.

기본은 토큰·쿠키 없는 **익명 공개 게시 문서 검색**이다. 가상 테스트·비공개 자료는 **연결 설정 → 문서 관리자 연결**에서 기존 서버의 공통 비밀번호로 로그인한다. 기존 `/api/v1/admin/login`·`/session`·`/logout`만 재사용하며 웹 로그인 세션을 자동으로 가져오지는 않는다. 비밀번호 입력은 전송 직전 비우고 저장하지 않는다. 관리자 토큰은 화면용 확장 토큰과 별도로 `storage.session`에만 보관하고 문서 `/chat`의 Authorization에만 사용한다. content script·페이지 DOM·로그·연결 JSON에는 전달하지 않는다. 문서·정답표를 자동 등록하거나 임베딩하지 않는다.

패널의 **문서 접근**에서 익명·관리자 연결·만료 상태를 확인한다. 만료·401/403은 관리자 세션을 정리하고 재로그인을 요구하며 익명 검색으로 자동 전환하지 않는다. **로그아웃 · 익명으로 전환**은 로컬 토큰을 지우고 서버 세션도 해제한다. 서버 연결 실패로 해제를 확인하지 못하면 옵션에 표시한다. 인증 상태가 바뀌면 진행 중 문서 요청과 문서 이력·근거를 정리하고 화면 안내는 유지한다. 만료 토큰은 다음 상태 확인/요청에서 제거하고 진행 요청도 세션 만료까지로 제한한다. 브라우저 종료·확장 재로드 시 관리자 세션은 다시 연결해야 한다.

문서 모드도 offscreen에서 한 번에 하나만 요청하며 자동 재시도하지 않는다. 문서 기한은 local/원격 모두 정적 설정 기본600초·1~1800초다. local 연결 JSON에 시간을 명시했다면 그 값을 유지하며, 연결이 없거나 시간 없는 기존 JSON은 문서600초·화면90초로 구분한다. 명시한90초도 임의로 늘리지 않는다. 취소·전환 시 fetch를 중단하고 늦은 응답을 폐기한다.

**`/api/v1/chat`과 화면 상담은 서버의 공통 budget/gate를 사용한다.** 본문 수신 middleware는 `min(OLLAMA_TIMEOUT,1800초)`로 제한한다. 수신 시작부터 계산하는 처리 budget은 요청 기한·서버 한도·1800초 중 작은 값이다. 문서 서버 한도는 `OLLAMA_TIMEOUT`, 화면은 이를 올림해1~1800초로 제한한 `settings.desktop_timeout_seconds`다. 독립 환경변수가 아니며, 이전 확장 DOM 요청의 시간 필드 누락만90초로 호환한다.

단일 프로세스 gate 점유 중 추가 추론 요청은429, 기한 초과는504, 연결 취소는499로 분류한다. 연결이 끊겼으면499 응답은 전달되지 않을 수 있다. 실행 중인 동기 DB·ONNX/native 작업을 떠나기 전에는 gate를 해제하지 않으며 GPU 추론의 즉시 중단은 보장하지 않는다. 취소 이후 다음 시험을 보내기 전에 기존 처리가 끝났는지 확인한다.

## 연결 설정과 처리 시간

- `DESKTOP_GUIDANCE_ENABLED`: 화면 상담 API 활성화 여부.
- `DESKTOP_EXTENSION_TOKEN`: 영문·숫자·`_`·`-`로 구성한 32~128자 연결 토큰.
- `DESKTOP_IMAGE_ENABLED`: 이미지 첨부 허용 여부, 모델의 vision 지원도 필요하다.
- `OLLAMA_LLM` / `LLM_NUM_CTX`: 공통 생성 모델과 문맥 길이.
- `OLLAMA_TIMEOUT`: 대기 시간(초), 화면 상담은 올림 후 1~1800초로 제한한다.
- `BACKEND_BIND_HOST`: 화면 상담은 `127.0.0.1`로 바인딩한다.

연결 JSON의 `timeoutSeconds`를 서버 설정에서 내보내 확장에 전달한다. 질문 준비·캡처도 전체 대기 시간에 포함한다. 서버는 남은 예산과 서버 한도 중 작은 값을 사용하고, 메타데이터 조회부터 생성 스트림 종료까지 제한한다. 시간 초과는 HTTP 504, 연결 종료에 따른 취소는 서버에서 499로 분류한다. 이미 끊긴 연결에는 499 응답이 전달되지 않을 수 있으며 자동 재시도하지 않는다. 연결 종료 시 서버도 조회/생성 HTTP 스트림을 닫은 뒤 처리 잠금을 해제한다. Ollama 엔진 자체의 즉시 추론 중단까지 보장하지는 않는다. 기존 3필드 연결 파일/시간 필드 없는 요청만 90초 호환값을 사용한다.

로컬 화면용 모델·토큰·이미지·JSON 시간 설정을 바꾸면 실제 서버에서 연결 파일을 다시 내보내 확장에 불러온다. 원격 문서 origin·정적 기한을 바꾸면 새 이름으로 재패키징하고 해당 확장을 다시 로드해야 하며 JSON으로 주소를 바꾸지 않는다. 아래 명령은 로컬 화면 연결용이며 저장소 루트에서 실행하고 파일 내용은 출력하지 않는다.

```cmd
if not exist .local mkdir .local
docker compose exec -T backend python -m BackEnd.desktop_connection /tmp/gyeote-extension-connection.json
docker compose cp backend:/tmp/gyeote-extension-connection.json .local/extension-connection.json
docker compose exec -T backend rm /tmp/gyeote-extension-connection.json
```

## EC2 전환 준비

### 일반 사용자용 문서 상담 패키지

소스 기본값은 로컬 `http://127.0.0.1:8000`이다. 배포 담당자는 승인된 **HTTPS API origin 하나**로 새 패키지를 만든다. 주소는 설치 파일에 고정하며 페이지 메시지·저장소·연결 JSON으로 바꾸지 않는다. 다음은 **접속하지 않는 더미 예시**다.

```cmd
node Extension/package.cjs --origin https://api.example.invalid --name remote-example --timeout 600
```

결과는 `.local/extension-packages/remote-example`이며 운영 파일 17개만 포함한다. 기존 출력은 덮어쓰지 않으므로 재생성할 때 새 이름을 사용한다. manifest의 정확한 호스트 권한과 options/offscreen CSP는 같은 origin으로 생성된다. 문서 요청 기한은 기본 **600초**, `--timeout`은 **1~1800초**다. 로컬 패키지는 origin을 `http://127.0.0.1:8000`으로 지정하며 명시된 연결 JSON 시간은 유지한다. 화면 연결의 시간 누락90초와 문서 기본600초는 별개다.

원격 패키지의 **공개 문서 상담에는 연결 JSON이 필요 없다.** 관리자는 연결 설정에서 직접 비밀번호를 입력한다. 세션은 해당 문서 서버에 묶이며 주소가 바뀌면 다시 로그인해야 한다. 원격 화면 안내·캡처는 제공하지 않으며 화면 토큰은 전송하지 않는다. 화면 안내의 공개 인증·남용 방지는 별도 설계가 필요하다.

배포 준비 순서는 다음과 같다. 실제 실행·배포 검증은 아직 수행하지 않았다.

1. 승인된 API 호스트의 DNS·TLS를 준비하고 기존 Compose `edge` 프로필/Caddy를 검토한다. `PUBLIC_API_HOST`가 HTTPS 호스트를 정하며 Caddy는 내부 진단·API 문서와 `/api/v1/desktop/*`를 차단한다. [운영 경계](../deploy/README.md)를 따라 백엔드8000·Ollama11434의 외부 공개 없이 edge가 내부 backend로 연결하게 한다.
2. 관리자 웹의 `VITE_API_BASE_URL`을 **같은 HTTPS origin, `/api` 제외**로 설정하고 프런트를 재빌드·배포한다. 기존 관리자 웹 진입 주소는 유지한다. 비밀번호·서버 키를 `VITE_*`에 넣지 않는다.
3. 설치·배포 방식에서 확정한 확장 ID의 `chrome-extension://32자ID`를 백엔드 `CORS_ALLOWED_ORIGINS`에 정확히 추가하고 기존 공식 웹/로컬 목록을 유지한다. CORS는 인증을 대신하지 않는다.
4. 실제 주소로 새 확장 패키지를 생성한 뒤 신규 설치→공개 상담→관리자 로그인/업로드→단절/복구를 확인한다. 실제 주소·확장 ID·인증서는 미확정이므로 현재는 **사용자 테스트 필요**다.

EC2 실행은 별도 기동·테스트 요청 후 진행한다. 변경 코드가 승인 후 원격에 게시된 경우, 초기 런타임 환경 주입 이후 갱신은 저장소에서 다음 두 명령을 사용한다. 현재 로컬 변경이 자동으로 EC2에 전달되는 것은 아니다.

```sh
git pull --ff-only
docker compose up -d --build
```

기존 Compose에 모델·토큰·이미지·시간 설정을 주입한다. 비교 시간은 해당 실행에서 합의한 예산에 다운로드·검증·복구를 포함해 제한한다. 기본 LLM은 유지하며, 새 VLM 시험은 별도 요청 후 실제 태그·digest·다운로드 용량·GPU/RAM·디스크·vision 지원을 확인한다. 파일 크기는 VRAM 사용량과 다르다. 임베딩·리랭커는 변경하지 않는다.

서버에서는 `mkdir -p .local` 후 위 Docker 내보내기·복사·임시 파일 제거 명령을 사용한다. 만든 비공개 JSON만 Windows에 안전하게 전달한다. 8000/11434는 외부에 공개하지 않고, 공개 Caddy의 `/api/v1/desktop/*` 차단을 확인한다. Windows의 8000 포트가 비어 있을 때 SSH 터널로 확장의 고정 주소를 유지한다.

```cmd
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=2 -L 127.0.0.1:8000:127.0.0.1:8000 -i 키파일경로 ubuntu@현재IP
```

동일 공개 화면·질문·DOM·이력으로 LLM과 VLM을 순차 비교하고 생성 모델 두 개를 동시에 상주시키지 않는다. 이미지 off/on, 답변 근거·대상 일치·시간·최대 메모리를 확인한다. 모델이 다르면 전체 구성 비교이며 이미지 효과만 입증한 것은 아니다. 교체 전 모델 태그/digest·문맥·옵션을 확보하고, 채택 전에는 원래 설정으로 복귀한다. bge-m3/1024·리랭커·DB·모델 캐시는 유지한다.
