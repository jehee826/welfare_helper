## 읽는 순서

2026-11-15 사용자 요청으로 [최종 잔여 계획](plan/final-plan.md)을 추가했다. 후속 상세 실행 순서·완료 기준은 이 문서에서 관리하고, 아래 기존 세 문서의 전체 상태·진행일지·현재 인계 역할은 유지한다. 아래의 세 문서 제한은 이 명시 추가 문서를 제외한 기본 운영 규칙이다.

1. **현재 구현을 이해하려면:** [전체 구조](design/architecture.md) → [RAG](design/rag.md) / [확장](design/extension.md) / [관리자](design/admin.md).
2. **작업을 이어가려면:** [현재 인계](plan/handoff.md) → [계획과 진행 현황](plan/merge_plan.md) → 연결된 [개발일지](plan/devlog.md) 순으로 읽는다. 활성 작업 문서는 이 세 개뿐이다.
3. **역할:** merge_plan은 계획·상태·잔여·일지 위치, devlog는 모든 실제 진행·실패·수정·검사, handoff는 지금의 작업·구현/배포 기준·차단·다음 행동을 관리한다. 새 문서는 목적·필요성·경로를 제시해 사용자 승인 후에만 만든다.
4. **과거 근거:** [보관 목차](archive/README.md)의 옛 계획·결정·검토·노트북 인계는 원문 보존용이며 별도 활성 계획이 아니다.
5. **자료 준비:** [수집 방법](data/수집방법.md) → [문서 포맷](data/문서포맷.md) → [문서 모음](data/문서모음/).

## 각 문서의 역할

- **design:** 현재 코드의 동작과 경계. 앞으로 만들 기능이나 당시 실패 일지를 섞지 않는다.
- **plan:** 위 세 문서만 사용한다. 계획/진행도는 merge_plan, 모든 상세 진행은 devlog, 현재 인계는 handoff에 둔다.
- **archive:** 기존 문서의 날짜와 전문을 보존한다. 옛 “현재/대기/완료”는 당시 상태다.
- **tests:** 판단 근거인 원자료. 대역·실제 모델·HTTP·사용자 UI 결과를 구분하고 정답표를 적재 원문에 섞지 않는다.

운영 실행은 [프로젝트 README](../README.md), [확장 README](../Extension/README.md), [배포 README](../deploy/README.md)를 따른다. 현재 환경·복구 위치·미완료는 [공유 인계](plan/handoff.md)에 기록하며 미래 계획의 별도 기준 문서로 늘리지 않는다.

## 업데이트 원칙

기본은 **기존 문서의 해당 절 갱신**이다. 최초 작성일을 보존하고 수정한 문서 상단에 `최신 업데이트: YYYY-MM-DD HH:mm KST`를 남긴다. 계획·실행·검증·테스트를 구분하며 새 계획을 구현 완료로 적지 않는다.

세 문서 외의 새 문서는 기존 문서로 수용하기 어렵더라도 목적·필요성·경로를 제시하고 사용자 승인을 받은 뒤 생성한다. 기존 README/현행 설계/지침은 제자리에서 갱신한다.

설계가 단일 작성자로 세 문서를 갱신하고 개발은 결과를 전달한다. 착수·단계 완료·중요 실패·범위/환경 변경·종료/인계 때 일지를 기록하고 계획의 상태/일지 링크와 현재 인계를 맞춘다. 과거 실패를 후속 성공으로 덮지 않는다.

## 원자료와 Git 공개 범위

루트 CSV는 기존 CSV 로더가 경로를 참조하므로 유지했다. DB 작업 SQL도 실행 파일이므로 이번 문서 정리에서 이동·수정하지 않았다. 현재 ERD 파일은 [복지챗봇.erd](design/database/복지챗봇.erd)에 있다.

자료 가이드와 공개 복지 문서는 docs/data에서 Git으로 공유한다. 현행 설계·세 작업 문서·기존 공유 문서의 archive 이동본·루트 AGENTS/CLAUDE·공통 스킬/진입점을 추적한다. 개인 기록·시험 원자료·다른 계획은 기존 제외 규칙을 유지한다.

명시적으로 공유한 프로젝트 지침/스킬 외의 개인 설정·백업·Word·실제 `.env`·키·모델/DB 데이터는 공개하거나 삭제하지 않는다. 문서 경로가 바뀐 것만으로 코드·DB·배포를 변경하지 않는다.
