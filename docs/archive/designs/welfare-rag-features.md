# RAG 데이터 필드와 역할

갱신: 2026-11-02. CSV 중심의 초기 구상과 현재 문서 업로드·확장 저장 경로를 구분한다.

## 현재 데이터 경계

| 구분 | 역할 |
|---|---|
| 부서·제도 메타데이터 | departments/welfare_programs의 이름·기관·출처 등. 검색 근거 원문 자체를 대신하지 않는다. |
| 문서·처리 작업 | rag_documents/rag_document_jobs의 업로드 원본·분석 결과·상태·후보 게시 정보 |
| 검색 벡터 | welfare_document_vectors의 현재 청크·1024차원 벡터·원문 위치·모델 식별 정보 |
| 상담·관리자 관련 | 조건·공개 상담·요약은 확장 chrome.storage.local, 관리자/화면 이력은 메모리, 토큰은 확장 세션이다. 기존 ERD 테이블 존재를 상담 DB 저장이나 공통 관리자 로그인 구현과 혼동하지 않는다. |

현재 ERD는 [복지챗봇.erd](../../design/database/복지챗봇.erd)다. 목업 ERD는 이전 구조 참고용이다. DB 변경 시 실제 적용 여부를 확인하고 ERD도 갱신한다.

## 원문과 검색 입력

Docling으로 PDF/DOCX/Markdown을 분석하고 문서명·제목 문맥·실제 원문을 이용해 청크를 만든다. 페이지/블록/char span·해시·임베딩 digest·tokenizer 정보로 추적한다. 숫자·금액·기간·부정·예외를 임의로 지우지 않는다.

bge-m3로 문서와 질문을 벡터화하며 기존1024차원과 모델 digest를 유지한다. 생성 모델만 변경하는 경우 재임베딩할 필요는 없다. 임베딩 가중치가 바뀌면 차원이 같아도 별도 호환 확인이 필요하다.

## CSV의 현재 위치

docs 루트의 공식 서비스 CSV와 활용가이드는 원자료다. CSV CLI는 현재 메타데이터 dry-run을 지원하며 이전 직접 벡터 적재를 기본 실행 경로로 안내하지 않는다. 업로드된 문서를 기존 워커로 처리한다. 공식 상세 수집 모듈의 존재를 최신 공식 상세가 DB에 모두 적재됐다는 근거로 사용하지 않는다.

## 접근 범위

test_only 자료와 정답표는 공식 서비스 근거로 노출하지 않는다. 테스트 원문은 관리자 검색 범위에서 확인하며 정답표는 적재하지 않는다. 실제 자료의 정확도는 서비스 ID·출처·기준일·내용을 대조해서 판단한다.
