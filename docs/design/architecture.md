## 사용자와 구성 요소

일반 사용자는 복지로의 Chrome 확장으로 복지 문서 질문과 공개 화면 안내를 이용한다. 웹은 관리자 로그인·제도/문서/연락처 기록 관리와 `/webchat` 단발성 공개 상담을 제공한다. 자동 클릭·입력·신청은 제공하지 않는다.

```text
복지로 Chrome 확장 ── HTTPS ──┐
                             ├─ EC2 edge → FastAPI → Ollama
Vercel 공개/관리자 React 웹 ─ HTTPS┘                │
                                              ├─ Supabase
문서 처리 worker ── Docling·청크·임베딩 ────────┘
```

- `Extension/`: Chrome MV3 content script, service worker, offscreen 문서로 UI·저장·HTTP 요청을 분리한다.
- `FrontEnd/`: React/Vite 공개 상담·관리자 정적 웹. Vercel에서 모델이나 Docker Compose를 실행하지 않는다.
- `BackEnd/main.py`: FastAPI 진입점. 공개 상담, 관리자 API, 화면 안내와 내부 진단을 연결한다.
- `BackEnd/documents/`: 원문 등록·작업·자동 처리·게시와 공통 문서 RAG.
- `BackEnd/rag/`: 저장소 검색, 임베딩·LLM 호출, 키워드 검색과 리랭커.
- Docker Compose: API·문서 worker·Ollama와 선택적 HTTPS edge. DB는 Supabase를 사용한다.

## 주요 처리 흐름

1. **문서 질문:** 확장 → `/api/v1/chat` → 접근 가능한 문서 스냅샷 → 대화 의도 준비 → 검색·재정렬·원문 보완 → LLM 답변 → 확장 표시·로컬 저장.
2. **화면 안내:** 확장 공개 DOM 수집 → `/api/v1/screen/guide` → LLM 설명·요소 선택 → 기존 DOM에 테두리 표시. 이미지 전송은 없다.
3. **문서 등록:** 관리자 인증 → 제도 선택·파일 업로드 → 작업 접수 → Docling 분석·청크·임베딩 → 성공한 버전 게시.

요청 처리와 자동 문서 처리는 서로 다른 실행 경로다. 업로드 접수 성공만으로 임베딩·게시가 완료된 것은 아니다.

## 데이터와 인증 경계

- Supabase에는 제도·부서, 원문·분석·처리 작업, 현재 검색 청크·벡터를 저장한다. 테이블 존재만으로 사용자 상담을 DB에 저장한다고 해석하지 않는다.
- 사용자 프로필과 공개 대화는 확장 `chrome.storage.local`에 저장한다. 저장 프로필은 추천 초안에 쓰고, 기본 OFF에서 현재 revision에 동의한 명시 ON에만 5필드를 최종 생성에 제공한다. 검색·prepare에는 보내지 않는다. 표시용 요약은 RAG에 보내지 않는다.
- 공개 질문과 관리자 검색은 문서 접근 범위가 다르다. `test_only`는 익명 사용자에게 공개하지 않는다.
- 관리자 인증은 서버 공통 비밀번호와 세션 방식이며, 영속 credential 파일 활성화 시 해당 파일을 사용한다. CORS나 확장 ID는 관리자 인증을 대신하지 않는다.
- 입력 개인정보 검사·출력 정제, 입력 예산, 문서 버전 일치, 실행 기한·취소 경계는 유지한다. 이 처리가 개인정보 탐지나 답변 정확도의 완전성을 보장하지는 않는다.

## 설정과 실행

확장 소스의 API는 `https://15.164.190.21`이며, 관리자 웹 API는 **빌드 시** `VITE_API_BASE_URL`로 결정된다. EC2 환경값만 바꿔서는 이미 배포된 정적 웹의 API 주소가 바뀌지 않는다. 클라이언트 통신은 HTTPS이고 SSH 터널은 제품 사용 경로가 아니다.

기본 실행 명령은 `docker compose up -d --build`다. GPU 사용에는 호스트 NVIDIA 환경과 Compose GPU 설정이 필요하다. 실제 운영은 별도 override·systemd 설정을 포함할 수 있으므로 저장소 기본값과 운영 적용값을 구분한다. 새 환경값은 컨테이너 재생성이 필요하다.

생성 모델·문맥·출력·기한은 환경 설정으로 주입한다. 모델을 바꾼다는 이유만으로 DB나 임베딩을 초기화하지 않는다. `.env`·키·모델 데이터·DB 데이터를 문서 정리나 초기화 대상으로 삼지 않는다.

공통 추론 gate는 **프로세스당 실행 3개·대기 0개**, 요청 기한은 서버·클라이언트 설정 중 짧은 값이며 최대 **1800초**다. 취소 응답이 native 작업이나 GPU 계산의 즉시 중단을 뜻하지 않는다. 다중 프로세스 전체에 걸친 공통 제한은 별도 설계가 필요하다.
