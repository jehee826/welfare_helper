## 사용자 화면

복지로 공개 페이지에서 플로팅 UI를 표시한다. 상단은 곁에·질문/안내 모드·내 정보·관리자 메뉴, 본문은 연속 대화, 하단은 입력창·마이크·전송 아이콘과 추천 질문 3개로 구성한다. 전송 중에는 정지 아이콘과 대기 말풍선을 사용한다.

내 정보 입력은 건너뛸 수 있고 수정할 수 있다. 저장된 조건은 추천 질문 초안에 사용한다. 추천 선택이나 음성 인식은 입력란을 채우며 자동 전송하지 않는다. 음성은 브라우저 SpeechRecognition 지원·권한이 필요하고, 명시적 시작과 취소·유한 기한을 둔다.

정보 사용 ON/OFF는 저장된 로컬 프로필이 있으면 바로 조작할 수 있고 선택 저장 중에만 중복 조작을 막는다. 모달·편집·사용 선택 읽기 오류·서버 지원 여부로 버튼을 막지 않는다. 클릭 때 로컬 사용 선택을 읽고 현재 프로필 revision으로 저장하며 서버 조회는 하지 않는다. 프로필 존재만으로 자동 ON하지 않는다. 실제 전송에서 동의·프로필 revision·서버 지원을 확인하고 최종 LLM 생성에만 제공한다.

답변의 본문·기관·전화·운영시간은 유지한다. 참고자료 패널·출처 열기·자료 대조일·저장 답변의 유효성 등 별도로 붙이던 보조 UI는 제거하며, 원문과 답변에 포함된 안내는 문자열 필터로 지우지 않는다. 내부 source/version/evidence 계약은 유지한다.

패널은 이동·접기·닫기·다시 열기를 제공한다. 실제 화면 안내의 클릭·입력·신청은 사용자가 한다. 관리자 메뉴는 기존 관리자 웹으로 이동하며 로그인 검증은 서버가 담당한다.

내 정보에는 확장 옵션 메뉴와 음성 입력 안내 토글을 표시하지 않는다. 관리자 웹은 ⋯의 관리자 접근으로 연다. 확장 옵션에는 안내와 관리자 웹 링크만 남기며 확장 자체 관리자 로그인은 제공하지 않는다. 마이크와 녹음 overlay의 전송 고지·30초 지원 안내·취소, 권한/오류 상태는 유지한다.

## 문서 질문과 로컬 저장

공개 상담은 **한 대화에서 최근 30문답(60메시지), 전체 저장 상한 4MiB**다. 질문·답변 한 쌍이 성공하면 원자적으로 저장하고 한도를 넘으면 오래된 완전쌍부터 제외한다. 기존 여러 상담은 이 형식으로 통합한다. 실패한 저장을 완료로 표시하지 않는다.

[worker.js](../../Extension/worker.js)가 `chrome.storage.local`의 단일 저장 경계를 담당한다. `TRUSTED_CONTEXTS`, sender·공식 최상위 탭, revision·generation·요청 소유권을 확인한다. 같은 요청의 중복 저장과 삭제·권한 변경 뒤 늦은 결과 반영을 막는다.

확장 상담은 항상 공개 문서를 사용하고 예전 관리자 접근값·토큰은 읽거나 전송하지 않는다. 공개 대화·프로필은 로컬에, 화면 안내 대화는 메모리에 보관한다. 관리자 웹의 인증·비공개 문서 접근 제한은 서버에서 유지한다. 기기 간 자동 동기화나 상담 DB 저장은 없다. 확장 제거·브라우저 데이터 삭제 시 보존을 보장하지 않는다.

사용자가 생성한 상담 요약은 기존 RAG 자동 맥락 `conversation.summary`와 별개다. worker가 `gyeote.displaySummary`에 마지막 성공본 하나를 저장하며, 필드는 `schemaVersion`·`revision`·`generation`·`conversationId`·`text`(최대1200자)·`partial`이다. 저장 시 현재 대화 revision·세대·ID와 요약 revision을 비교하고 직렬화한다. 기존 대화 schema3는 변경하지 않는다.

상단 내 정보 왼쪽의 상담 요약 버튼은 항상 클릭해 기존 모달 틀의 요약 창을 열 수 있다. 창에는 저장한 마지막 요약과 별도의 요약하기 버튼이 있다. 내부 버튼은 공개 접근·중복 요약·저장 대화 유무만 확인하고 화면 모드·다른 질문 진행·미저장 답변으로 실행을 차단하지 않는다. 기존 worker→offscreen→백엔드 요약 POST→worker 저장 경로와 저장 충돌 처리를 재사용한다. 창 열기만으로 생성 요청을 보내지 않는다.

수동 요약은 보관된 최근30문답 전체에서 최대60메시지/12000자의 최근 완전쌍을 선택하고, 한도를 넘으면 partial로 표시한다. RAG의 자동7일/주제/정보OFF 경계는 수동 입력에 적용하지 않으며 자동 contextMessages/requestContext 자체는 유지한다. F5 후에도 저장본을 창에서 다시 볼 수 있고, 닫기는 저장값을 지우지 않는다. 새 성공본으로 교체하며 대화 삭제·재설정은 요약도 함께 지운다. 취소·실패·늦은 결과는 이전 성공본을 덮지 않고 표시용 요약을 검색·prepare·후속 RAG 요청·DB에 포함하지 않는다.

새 주제 응답의 `resetTopic`은 저장된 assistant 메시지의 `topicStart`로 연결된다. 이전 대화는 화면에 남지만 다음 요청의 맥락 범위는 최신 주제 경계부터 잡는다. 옛 요약의 저장 호환과 현재 RAG 활용은 [RAG 설계](rag.md)처럼 구분한다.

## 화면 안내

공개 DOM의 제한된 후보 이름·주변 문구와 질문을 전송해 설명과 **0~3개 요소 강조**를 받는다. 현재 제품 경로에 이미지 캡처·VLM 전송은 없다. 입력값·관리자 토큰·저장 프로필·문서 맥락을 화면 요청에 섞지 않는다.

확장 DOM 후보 수집·예산·모델 선택·응답 대상 검증을 거쳐 실제 존재하는 요소를 표시한다. 문서 RAG 검색과 별도 경로다. 메뉴 대신 검색창을 선택하는 등 의미 선택 품질 문제는 기능 연결 성공과 별도로 남을 수 있다.

## 통신과 취소

`content.js`의 UI 요청은 worker와 offscreen을 통해 EC2 HTTPS API로 전달한다. 현재 API origin은 `https://15.164.190.21`이다. 클라이언트용 로컬 연결 JSON·SSH 터널·로컬 Ollama는 필요하지 않다.

- 문서: `/api/v1/chat`, 소스 기본 기한 **600초**.
- 화면: `/api/v1/screen/guide`, 최대 **90초**, 설정된 문서 기한이 더 짧으면 그 값 이내.
- 관리자 웹: `https://welfare-helper-iota.vercel.app/admin/documents`.

취소·모드 전환·권한 변경·오래된 요청 결과를 구분한다. Alt+Tab으로 다른 창에 이동하는 것과 브라우저 탭 전환은 동일한 이벤트가 아니며, 제품의 실제 포커스 동작은 별도 확인 기록을 따른다. 정지 아이콘은 요청 취소이지 서버 GPU 즉시 정지 보장은 아니다.
