## 구현된 경로

- 웹 문서 등록: 관리자 공통 비밀번호 → 제도 선택 → 업로드 → Docling 자동 분석·청크·임베딩·게시. 수동4섹션 검토와 색인 승인은 사용 절차에서 제거됐다.
- 문서 RAG: 현재 조건·최근 대화·요약으로 의도 준비 → dense+BM25/RRF → ONNX 리랭커 → 같은 문서/버전의 조건·예외 보완 → 원문 기반 생성·인용/숫자/연락처 대응 검사.
- Chrome 확장: 명시적 화면/문서 모드, 공개 DOM 기반 설명·0~3개 CSS 테두리, 모드별 이력·취소·오래된 응답 정리.
- 문서 관리자 연결: 기존 서버 로그인·세션·로그아웃 사용. 화면용 연결 토큰과 문서 관리자 세션을 분리한다.
- 확장 조건·공개 상담·요약은 chrome.storage.local에 보관한다. 성공한 질문/답변과 요약을 함께 저장하고 revision·권한·quota 오류를 처리한다. 관리자/화면 이력은 메모리, 토큰은 확장 세션이며 다른 기기 동기화·DB 상담 전체저장은 제공하지 않는다. React 웹은 관리자 전용이며 공개 상담은 확장에서 이용한다. 이 변경의 Vercel 배포는 아직 완료하지 않았다.
- 추천 질문 최대3개와 음성 결과는 초안만 입력한다. 음성은 명시적 클릭·한국어·최대30초이며 사용자 확인 후 직접 전송한다.
- HTTPS 문서 패키지의 정적 origin·기한·세션 origin·정확한 CORS를 준비했다. 기본 원격 문서는 연결 JSON이 불필요하다. 원격 DOM 안내는 서버·패키지 양쪽의 명시 설정으로만 제공하며 기본off다. 원격 이미지/desktop 토큰·프로필·문서 요약 전송은 허용하지 않는다.

## 확인 범위와 남은 문제

| 영역 | 확인한 범위 | 남은 점 |
|---|---|---|
| 문서 RAG | 실제3서비스·67청크·1024차원 게시. Qwen1.5B 서비스9문항 유효0, 전체16문항 out_of_scope13/입력예산3 | 실제 품질 미통과. 이후 원문 선택/비용 보완은 모델0회 검사이며 실제 품질 재평가 필요 |
| 조건·상담·초안 | 조건/F5·자동상담저장·정상 Chrome 재실행 복원·개별삭제·모드분리·음성 초안은 사용자 확인, 맥락 전달/요약 저장은 내부 확인 | 복원 상담 후속질문·격리 프로필 모름/삭제, 실제 요약 의미 품질은 남음 |
| 화면·패널 | 기본 작은 창/Tab/스크롤·드래그·접기/닫기 사용자 확인, 격리 Chromium320×568 실제 레이아웃 확인 | 실제 복지로 강조 가림/스크롤·자연어 의미·이미지 효과는 별도 평가 |
| 연결·배포 | HTTPS 문서 패키지·권한 경계와 기본off 원격 DOM 로컬 검증 완료 | 실제 API/TLS/확장 ID·Vercel/EC2 재배포·운영 단절복구·원격 화면은 미검증 |

과거 MD 소수 문항 성공·이미지1건 성공을 현재 운영 품질로 확대하지 않는다. 기존 LLM을 유지하며 이미지 경로는 향후 비교용이다. ValueError만으로 VLM 성능 부족이나 메모리 부족을 단정하지 않는다.

인용의 원문 부분문자열·숫자/연락처 대응 검사는 모든 문장의 의미나 최종 자격 판정이 아니다. 별도 연락처 목록·연계는 현재 공통 QA의 완료 기능이 아니며 근거 없는 기관/연락처를 생성하지 않는다. 문서/화면 요청은 공통 서버 budget/gate로 관리하지만 동기 native 작업·GPU 추론의 즉시 중단을 보장하지 않는다.

## 현재 기준과 운영 시 주의

실행은 [프로젝트 README](../../README.md)와 [확장 README](../../Extension/README.md)를 따른다. 현재 제품 화면 안내는 Extension이며 Desktop/Electron은 이전 구현 참고다. 상세 계획·실행·검증·테스트 설명은 로컬 태스크 계획에 통합했고 날짜순 이력은 development, 현재 상태는 handoff에 둔다. 원시 측정 자료는 tests/results에 보존한다.

공개 요청 사용량은 단일 프로세스 IP 예산이며 공통 실행1/대기0 gate와 역할이 다르다. proxy 주소는 명시된 신뢰 홉만 사용한다. CORS·확장 ID·IP 제한은 관리자 인증이나 다중 서버 공통 제한을 대신하지 않는다. 의존성 잠금·로컬 설치/빌드 검증은 완료했으나 원격 CI·GPU 적재는 별도다.

Supabase Auth 가입을 관리자 필수 절차로 되살리지 않는다. DB는 기존 스키마를 사용하고 앱 시작 시 자동 DDL/초기화를 하지 않는다. 공식 복지서비스로 배포하기 전에는 자료 최신성·접근 통제·상담 한계·실제 사용자 흐름을 별도 검증한다.
