# 현재 구현과 남은 차이

갱신: 2026-11-01. 기존10월27일 main 분석을 현재 확장 개발 브랜치의 코드·확인 결과에 맞춰 교체했다. 배포 환경이 이 소스와 같다는 뜻은 아니다.

## 구현된 경로

- 웹 문서 등록: 관리자 공통 비밀번호 → 제도 선택 → 업로드 → Docling 자동 분석·청크·임베딩·게시. 수동4섹션 검토와 색인 승인은 사용 절차에서 제거됐다.
- 문서 RAG: dense+BM25/RRF → ONNX 리랭커 → 최소 근거 프롬프트. 실제 검색 원문·출처 표시.
- Chrome 확장: 명시적 화면/문서 모드, 공개 DOM 기반 설명·0~3개 CSS 테두리, 모드별 이력·취소·오래된 응답 정리.
- 문서 관리자 연결: 기존 서버 로그인·세션·로그아웃 사용. 화면용 연결 토큰과 문서 관리자 세션을 분리한다.
- 웹 조건·상담 기록은 브라우저 저장 기능을 사용한다. 다른 기기 간 동기화나 계정 저장을 완료 기능으로 표현하지 않는다.

## 확인 범위와 남은 문제

| 영역 | 확인한 범위 | 남은 점 |
|---|---|---|
| 문서 RAG | 가상 MD·실제 임베딩/검색·두30B 모델의3문항 | PDF/OCR 다양성, 실제 복지 자료, 다중 턴, 장기 정확도 |
| 화면 안내 | 실제 복지로에서 대상·색·번호 표시 | 기능/위치 설명 오류, DOM에 없는 정보 |
| 선택 이미지 | 실제 단일 대상 안내1건 | 3건 중2건 ValueError의 구체 조건, 이미지 추가 효과 |
| EC2 실행 | 실제 GPU·모델 비교·복구 | 표준 전체Compose 빌드와 Spot 단절을 포괄 검증한 것은 아님 |

기존 LLM을 유지하며 이미지 경로는 향후 비교용이다. 오류코드를 확인하지 않고 VLM 성능 부족이나 메모리 부족으로 단정하지 않는다.

## 현재 기준과 운영 시 주의

실행은 [프로젝트 README](../../README.md)와 [확장 README](../../Extension/README.md)를 따른다. 현재 제품 화면 안내는 Extension이며 Desktop/Electron은 이전 구현 참고다. 상세 시험 결과·실행 상태는 로컬 tests/results와 log/handoff로 분리한다.

Supabase Auth 가입을 관리자 필수 절차로 되살리지 않는다. DB는 기존 스키마를 사용하고 앱 시작 시 자동 DDL/초기화를 하지 않는다. 공식 복지서비스로 배포하기 전에는 자료 최신성·접근 통제·상담 한계·실제 사용자 흐름을 별도 검증한다.
