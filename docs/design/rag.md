## 입력과 대화 맥락

`/api/v1/chat`, `/debug/rag`, 관리자 문서별 query가 공통 [answer_document](../../BackEnd/documents/qa.py)를 사용한다. 관리자 search API는 답변 생성 없이 dense 검색을 수행한다.

저장된 내 정보는 추천 질문용이다. 구형 API의 `profile` 필드는 호환을 위해 받을 수 있지만 검색·생성에 반영하지 않는다. 직접 사용자 발화의 조건과 저장 프로필을 구분한다.

[prepare_context](../../BackEnd/documents/context.py)는 관련 대화가 있으면 기존 모델을 최대 1회 호출해 `independent`·`followup`·`unclear`와 독립 검색질문을 준비한다.

- **새 주제:** 현재 질문 원문으로 검색한다. 모델이 선택한 과거 조건·문서 참조를 섞지 않는다. 지원 클라이언트에는 `resetTopic`을 반환한다.
- **후속 질문:** 최근 문답을 의미 해석에 사용하고, 선택된 직접 사용자 원문과 관련 문서의 이름·ID로 검색질문을 재구성한다. 챗봇 발화는 사실 근거나 확인된 사용자 조건이 아니다.
- **불명확:** 확인이 필요하다는 상태를 전달한다. 참조 서비스가 여러 개면 서비스 선택 질문으로 조기 반환할 수 있다.
- **준비 실패:** 현재 질문을 유지하고 맥락 누락을 표시한다. 최근 두 문장을 무조건 붙이지 않으며 취소·기한 초과는 삼키지 않는다.

최근 이력은 최대 **12메시지·6000자**, 직접 사용자 원문 목록은 최대 **30개·6000자**, 재구성 검색질문은 최대 **600자**다. 과거 요약 DTO와 저장 필드는 호환용으로 남아 있지만, 현재 준비·최종 생성에는 출처 없는 옛 요약을 쓰지 않는다. 현재 경로가 새로운 장기 요약을 계속 생성한다고 설명하지 않는다.

## 검색과 리랭커

1. 권한에 맞는 현재 게시 문서·성공 작업·벡터 스냅샷을 읽는다.
2. 임베딩 모델 digest가 맞는 청크를 대상으로 검색질문을 임베딩한다.
3. dense 코사인 검색과 BM25 키워드 검색 후보를 구한다.
4. **양쪽 후보 모두** `min_similarity` 이상의 코사인 점수를 요구한 뒤 RRF로 결합한다. BM25 결과라고 cutoff를 우회하지 않는다.
5. 리랭커로 재정렬한 뒤 핵심 원문을 고른다. 실제 사용 개수는 설정값을 따른다.

검색할 자료가 없거나 기준을 통과한 후보가 없으면 근거 부족 응답과 확인된 문의처를 반환한다. **검색 점수가 기준 미달이라는 사실은 문서 전체에 해당 사실이 없음을 증명하지 않는다.** 후보가 있는데 생성 모델이 `no_evidence`로 판단하는 경우와도 구분한다.

현재 저장소는 DB 스냅샷을 받아 Python에서 유사도를 계산한다. 벡터가 pgvector에 저장됐다고 DB ANN 검색을 사용한다고 설명하지 않는다. BM25는 스냅샷·권한·모델 조건이 일치할 때 제한된 인덱스 1개를 재사용하며 질문·답변 캐시는 아니다.

## 원문 전달과 답변 생성

[complete_sources](../../BackEnd/documents/welfare.py)는 검색된 문서의 **동일 버전** 안에서 부모 원문과 대상·조건·예외·지원·신청 관련 절을 보완한다. 현재 제목 패턴에 따른 원문 선택은 남아 있으며, 모든 문서를 통째로 넣는 구조는 아니다.

입력 예산에 맞춰 문서·버전 단위로 원문을 넣거나 제외한다. 첫 문서의 최소 원문도 담을 수 없으면 보류한다. 최종 프롬프트에는 현재 질문, 재구성한 검색 의도, 선택된 직접 사용자 발화, 이번 원문을 구분해 넣는다. 과거 챗봇 답변·저장 프로필·옛 요약은 최종 사실 근거가 아니다.

최종 생성은 최대 1회다. 지침은 문서에 근거한 구체적 설명, 지역·기간·대상·예외 구분, 확인되지 않은 개인 자격 단정 금지, 설명 후 필요한 조건 질문을 요구한다. 일반 복지 질문에서 검색을 건너뛰고 모델 지식만으로 답하는 범용 라우터는 없다.

## 검사와 응답 계약

모델 출력은 `status`와 `text`의 JSON이다. status는 `answer`, `clarify`, `no_evidence`, `out_of_scope`, text는 **1~3000자**다. 빈 응답·형식 오류는 실패 처리한다.

최종 답변의 정확한 연속 인용문·숫자 집합을 대조하던 의미 검사는 현재 경로에서 제거됐다. **권한·개인정보·참조 범위·입력 예산·응답 형식·실행 기한·문서 스냅샷과 임베딩 digest 일치**는 유지한다.

API의 `evidence`는 서버가 실제 모델 입력에 제공한 검색 원문이다. `role: retrieved`, 빈 `quote`와 원문·문서 ID·출처·페이지 등을 연결한다. 이는 LLM의 문장별 인용 인증이나 모든 문장의 사실 일치 보장이 아니다. 프런트에서도 참고자료와 검증된 인용을 혼동하지 않는다.

## 남은 한계

검색어 재구성·주제 판정·최종 답변의 의미 정확도는 별도 평가 대상이다. cutoff는 자료와 검색질문 변화에 따라 평가해야 하며 고정값만으로 보장되지 않는다. 날짜 메타데이터만으로 현행 운영을 단정해서도 안 된다.

대화 시간 TTL은 현재 context DTO에 없다. 오래된 대화를 화면에 보존하는 것과 자동 맥락에서 제외하는 기준은 별도 결정 사항이다. 새 구조나 재시험은 [협업 계획](../plan/collaboration-plan.md)에서 범위를 정한 뒤 진행한다.
