# 다음 개선 순서

갱신: 2026-11-01. 이전 Supabase Auth 가입·수동 검토 추가 계획은 현재 구현과 맞지 않아 교체했다. 기본 생성 모델은 기존 LLM 유지로 확정됐다.

## 1. 화면 답변과 실제 표시의 일치

실제 대상ID·색·번호·요소명 검증을 유지한다. 위치는 DOM의 실제 정보와 일치하도록 다루고, 모델의 추정 방향 문구를 그대로 신뢰하지 않는다. 현재 기능 설명 오류와 위치 오류를 구분해 개선한다. 자동 클릭·입력·신청 기능을 추가하지 않는다.

## 2. 답변 검증의 원인 구분

이미지 시험2건에서 ValueError가 관측됐다. 현재의 일반 오류만으로 방향표현·민감문구 등 세부 거절 조건을 확정할 수 없다. 비밀이나 원문 전체를 남기지 않는 고정 오류코드부터 검토한다. 보호 검증을 제거하거나 고정정답으로 통과시키지 않는다. VLM 전환은 그 뒤 별도 요청·예산으로 비교한다.

## 3. 문서 RAG 품질

공식 원문을 준비하고 조건·예외·없는 정보 질문을 기준으로 추출→청크→검색→리랭크→생성을 나눠 평가한다. 현재 가상 MD3문항 성공은 운영 정확도 보장이 아니다. PDF 표/OCR·여러 유사 문서·다중 턴을 순차 확인한다. 정답표는 검색 자료에 넣지 않는다.

## 4. 실행 재현성과 기록

표준 Compose 전체 빌드·최초 모델 준비·네트워크 단절은 실제 실행 범위를 구분해 확인한다. 현재 화면 상담의 서버 기한/취소와 문서 /chat의 차이를 유지해서 설명한다. 문서·검색 계약 변경과 DB 변경이 있으면 관련 문서 및 ERD를 함께 최신화한다.

하위 작업 완료·실패·중요 상태 변경마다 로컬 개발일지와 인계문서를 갱신한다. 사용자 서비스·캐시·원본을 보존하고, 클라우드 실행과 추가 모델 다운로드는 해당 작업 범위의 승인을 따른다.
