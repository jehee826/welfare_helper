# 다음 개선 순서

갱신: 2026-11-02. 완료한 로컬 구현과 남은 실제 검증을 구분한다. 기본 생성 모델은 기존 LLM을 유지한다.

## 1. 화면 답변과 실제 표시의 일치

실제 대상ID·색·번호·요소명 검증을 유지한다. 범례는 현재 DOM label/role만 사용하고 모델 meaning을 기능 사실로 덧붙이지 않는다. 패널 글자·포커스·viewport/가림 정리를 보완했으나 작은 창·키보드·스크롤은 사용자 테스트가 필요하다. 자연어 기능 설명 정확도는 실모델 재평가 전 미검증이며 자동 클릭·입력·신청을 추가하지 않는다.

## 2. 답변 검증의 원인 구분

이미지 시험2건에서 ValueError가 관측됐다. 현재의 일반 오류만으로 방향표현·민감문구 등 세부 거절 조건을 확정할 수 없다. 비밀이나 원문 전체를 남기지 않는 고정 오류코드부터 검토한다. 보호 검증을 제거하거나 고정정답으로 통과시키지 않는다. VLM 전환은 그 뒤 별도 요청·예산으로 비교한다.

## 3. 문서 RAG 품질

실제3서비스·67청크 게시 후 Qwen1.5B 서비스9문항의 유효 답변은0건이었다. 이후 원문 범위/입력 비용 보완은 모델0회 검사이며 정확도 재평가가 아니다. 승인 환경에서 현재 생성 모델을 같은 고정 질문으로 평가하고 조건·예외·보류·후속/요약 의미를 구분한다. PDF 표/OCR·여러 유사 문서는 입력 원문 준비와 구조/실모델 검증을 분리한다. 정답표는 검색 자료에 넣지 않는다.

## 4. 실행 재현성과 기록

문서 /chat과 화면 상담은 공통 서버 기한·연결 취소·단일 프로세스 gate를 사용한다. native 작업을 떠나기 전 gate를 유지하고 GPU 즉시 중단·서버 여러 인스턴스의 전역 잠금은 보장하지 않는다. 정적 HTTPS 문서 패키지는 준비했으며 실제 TLS/확장 ID/CORS·관리자 웹 API 주소·단절복구는 승인 환경에서 확인한다. 원격 화면 안내는 별도 인증·남용 제한 설계 전 미제공이다. DB 스키마를 변경할 때만 실제 적용과 ERD 갱신을 함께 검토한다.

하위 작업 완료·실패·중요 상태 변경마다 로컬 개발일지와 인계문서를 갱신한다. 사용자 서비스·캐시·원본을 보존하고, 클라우드 실행과 추가 모델 다운로드는 해당 작업 범위의 승인을 따른다.
