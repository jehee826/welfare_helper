# 병합 후 확정 사항

작성: 2026-11-08. 최신 업데이트: 2026-11-08 21:36 KST

확정된 결정만 기록한다. 실행 순서·검증·미완료 항목은 [merge_plan.md](merge_plan.md)에서 관리한다.

- **담당:** Codex가 BackEnd·FrontEnd·Extension 전체 검토·수정·테스트를 단독 진행한다.
- **브랜치:** 병합된 main `eb760b6` 기반 `codex/fix-merge`에서 작업한다. main 직접 수정·커밋·push는 하지 않는다.
- **완료 흐름:** 결함 해결 → 기존 계획 적용·정상 동작 확인 → 배포 검증 → 최종 main PR. Codex가 push·PR 생성, 사용자가 최종 검토·병합 승인한다.
- **EC2:** 사용자가 켠 뒤 필요한 실제 시험을 진행한다. 기동 자체가 배포·재시작·DB 쓰기·비밀번호 교체 승인을 뜻하지 않는다.
- **W02 자료 확대:** 제공된 new 정리본357개 중 시연용 부모급여 지원(WLF00004657)·국민취업지원제도(WLF00003245)·청년월세 지원사업(WLF00004661)은 제도/문서 모두 미등록으로 유지하고, 게시된 아동수당(WLF00001171)은 중복 등록하지 않았다. 신규353개를 정상 관리자 API/기존 worker의 Docling·실제 임베딩·자동 게시로 추가해 기존11개를 보존한 총364개 공개를 확인했다. 관리자 UI는 필수가 아니며 필요한 발행기관 부서 메타데이터만 추가했다. 원본/미추적 자료·기존 문서·DB 스키마·모델 파일/정밀도는 보존했고 EC2 중지/자동 부팅 회귀는 별도 복원 후 마쳤다.
- **W02 후속 평가:** 전체 적재 뒤 실제 상담 시험을 분리한다. 신규 코퍼스 시험은 요청당100초 이내·주제 전환 때 이전 조건/문서 미혼입·명시ON이어도 저장 정보 없이 먼저 검색한 뒤 후보를 일치/불일치/정보 부족으로 비교하는 기준이다. 전수1092건은 실제 호출 전에 총10건으로 축소했고, 대표4문서의10건 공개API 시험을 완료했다. HTTP200/계약유효10건, 시간1건 통과/9건 미달, 내용 오류6건·주의3건·원문 부합1건으로 시간·내용 동시 통과는0건이다. 검색/준비의 실제 프로필 입력은 라이브 비관찰이며 설치 Chrome 표시 시간이나 전체364개 품질 검증으로 확대하지 않는다. 기존 동시3건 목표와 timeout·제품/모델 설정은 바꾸지 않으며 세부 실측은 merge_plan 6절에 보존한다.
- **EC2 부팅 경로:** 구버전 checkout의 compose 재빌드 대신 이미지 해시를 확인한 기존 컨테이너를 Ollama→backend→edge/worker 순서로 시작하고 준비 상태를 확인한다. 현재 backend8a289b8·worker2a15ccd·Ollama74129cd·기존edge의 실제 이미지와4개 핀이 일치한다. 이후 이미지 교체 시 핀도 함께 갱신해야 하며 불일치하면 기동을 중단한다. 기존 unit의 시작/중지 명령만 drop-in으로 바꾸고 모델·DB·비밀 환경·마운트를 보존했다. 정적/기동 경로 검사는 통과했으나 실제 EC2 재부팅 종단은 아직 미검증이다.
- **자료 갱신:** 사용자가 추가·갱신 자료를 제공할 때 공식 출처·기준일·기존 게시본과 대조해 수동 반영한다. 자동 수집·정기 갱신 기능은 이번에 만들지 않는다.
- **W04 지원 범위:** Windows 11·최신 안정판 Chrome에서 확장·관리자 웹을 검증한다. 확장은 기존 개발자 모드 설치를 유지하며 macOS·다른 브라우저·웹스토어 배포는 이번 완료 조건에서 제외한다.
- **W04 처리·속도:** 초기60초는 기존 모델을 유지하는 코드/실행 구조 개선으로 검증한다. 해당 범위에서 일관된60초 달성이 어렵다고 판단되면80초로 완화한다. 동시3건61~72초 관측과 단건/묶음 대조 실패를 근거로 **현재 완료 기준은 동시 추론3건, 각 요청80초 이내 최종 답변 표시**로 적용한다. 모델 준비 후 동시 전송 시점부터 각각 측정하며 HTTP 완료와 실제 Chrome 최종 표시는 구분한다.
- **모델 불변:** Qwen3와 리랭커의 기존 모델 파일·태그·가중치·Modelfile·정밀도/양자화는 바꾸거나 새로 내려받지 않는다. 속도를 위해 KV/추론 정밀도·컨텍스트/출력 한도를 조정하지 않는다. 병렬/스레드·gate·자원 분리·상주/재사용·중복 I/O/호출 제거 등 실행 구조만 최적화한다. 이전KVq8/Flash명시ON 시험은 f16/auto로 복구했으며 반복하지 않는다. 리랭커는 원래의 model_quantized.onnx를 그대로 사용하고 묶음 후보는 대조 실패로 채택하지 않는다.
- **모델 메모리:** EC2의 기존 LLM은 상시 메모리에 유지하고, Docling은 문서 처리 시에만 로드해 작업 종료 후 해제한다. 문서 작업 감시·연락처 만료 삭제 worker와 디스크 모델 캐시는 유지한다. 실제 메모리 여유·임베딩 모델 공존·동시 3건 성능을 검증한다.
- **W08:** 마지막 실제 사용자 발화로부터 **7일 이상**이면 history·요약·문서 참조·직접 조건을 자동 맥락에서 함께 제외한다. 화면 기록은 보존한다.
- **W12:** 별도 반응형 상담 웹은 이번에는 **설계만** 한다. 구현·배포는 후속 작업이며, 이번 제품 개발은 확장·관리자 웹을 완료 대상으로 한다.
- **W13 정보 사용:** 기본 OFF. ON일 때만 저장 정보를 EC2의 최종 답변 생성에 제공하며 검색·검색 준비에는 사용하지 않는다. OFF 전환 시 화면 기록은 보존하고 자동 맥락은 새로 시작한다.
- **W13 조건 비교:** 질문 기반 검색 후 공식 원문과 사용자 조건을 비교해 **맞는 후보 안내 / 확인된 불일치는 이유를 알리고 추천 제외 / 정보 부족은 제외하지 않고 추가 질문**으로 구분한다. 모두 불일치하면 “현재 조회된 제도 중 입력하신 조건에 맞는 제도를 찾지 못했습니다”라고 안내한다. 추천을 최종 수급 자격 확정으로 표현하지 않는다.
- **W14:** **연락처 안내 기록만 90일 보존 후 자동 삭제**, 관리자 기간별 삭제 허용, 공개 상담 화면에 익명 안내 건수 수집 고지. 질문·답변 쌍/본문·요약·프로필·IP는 저장하지 않는다.
- **W15:** **DB 스키마 변경 없이** 현재 비밀번호 입력 → 새 비밀번호 발급·일회 표시 → 이후 새 비밀번호로 접근한다. 분실 비밀번호 복구 기능은 추가하지 않는다.
- **W06/W07 크기:** 기본400×720px·최소320×360px·방향키20px·제목줄 더블클릭 위치 복귀를 유지한다. 새 UI 요청으로640×900px 제품 상한을 제거하고 현재 콘텐츠 viewport에서 각 변 최소4px 여백까지 확장한다. 저장 검증의 기술 상한은 각 변16384px, 기존schemaVersion1/저장값은 호환한다. 창 축소는 표시만 제한하고 선호 크기·자유/오른쪽 배치·F5 복원·revision/실패 계약은 보존한다.
- **W07 불투명도:** 질문/안내 바로 왼쪽의 표시 문구 없는 가로 슬라이더 하나로10~100%/1% 간격·기본100%를 유지한다. 최신 정정에 따라 배경 전용 대신 **플로팅 UI 전체**에 적용한다. 패널의 제목줄·말풍선·글자·입력·버튼·토글을 한 번에 합성하고 분리된 내 정보/⋯ 모달 카드·다시 열기 버튼도 각각 한 번만 적용한다. 원래 색·비활성 상태 표시는 유지하고 자식에 같은alpha를 중첩하지 않는다. 사이트·모달 배경막·DOM 강조는 조절하지 않는다. 접근성 이름/title·입력 즉시 반영·포인터 종료1회/키보드400ms 저장·기존 저장 형식/revision·기본값 복원을 유지한다.
- **확장 모달·제목줄:** 내 정보와⋯는 사이트 콘텐츠 viewport 전체 배경 위의 단일 모달로 분리한다. 네 모서리 둥근 창·내부 스크롤·배경 입력/스크롤 차단·포커스 순환/복귀·×/Esc 닫기를 적용하고 대화·초안·미저장 정보·기존 요청 계약을 보존한다. OS/브라우저 전체 화면은 사용하지 않는다. 내 정보는60×44px, ⋯/−/×는44×44px 둥근 사각형, 질문/안내는 최소64px로 넓히고320px에서는 슬라이더·모드를 두 번째 줄에 나란히 배치한다.
- **W16 디자인:** 기능 검증 후 Codex가 복지로와 어울리는 색상·글자·여백·상태 표시를 정리한다. 기존 조작과 기능·인증·저장 계약은 유지한다.
