## 1. 화면 답변과 실제 표시의 일치

실제 대상ID·색·번호·요소명 검증을 유지한다. 범례는 현재 DOM label/role만 사용하고 모델 meaning을 기능 사실로 덧붙이지 않는다. 작은 창의 입력/버튼 접근·Tab 포커스·패널 조작은 사용자 확인을 마쳤다. 실제 복지로 강조의 가림·스크롤과 자연어 기능 설명 정확도는 별도 검증이 남으며 자동 클릭·입력·신청을 추가하지 않는다.

## 2. 답변 검증의 원인 구분

과거 이미지 시험2건에서 ValueError가 관측됐다. 당시 일반 오류만으로 방향표현·민감문구 등 세부 거절 조건을 확정할 수 없다. 문서 QA에는 원문을 남기지 않는 고정 단계·코드·소요시간 진단을 구현하고 정상/실패 최소검사를 마쳤다. 이 결과가 과거 이미지 실패 원인을 규명한 것은 아니다. 보호 검증을 제거하거나 고정정답으로 통과시키지 않으며 VLM 재시험은 별도 범위로 남긴다.

## 3. 문서 RAG 품질

실제3서비스·67청크 게시 후 Qwen1.5B 서비스9문항의 유효 답변은0건이었다. 이후 원문 범위/입력 비용 보완은 모델0회 검사이며 정확도 재평가가 아니다. 승인 환경에서 현재 생성 모델을 같은 고정 질문으로 평가하고 조건·예외·보류·후속/요약 의미를 구분한다. PDF 표/OCR·여러 유사 문서는 입력 원문 준비와 구조/실모델 검증을 분리한다. 정답표는 검색 자료에 넣지 않는다.

## 4. 실행 재현성과 기록

문서 /chat과 화면 상담은 공통 서버 기한·연결 취소·단일 프로세스 gate를 사용한다. native 작업을 떠나기 전 gate를 유지하고 GPU 즉시 중단·서버 여러 인스턴스의 전역 잠금은 보장하지 않는다. 정적 HTTPS 문서 패키지와 기본 비활성 원격 DOM 경로를 준비했으며 실제 TLS/확장 ID/CORS·관리자 웹 API 주소·운영 단절복구는 배포 환경에서 확인한다. 로컬 구현을 실제 배포 성공으로 취급하지 않는다. DB 스키마를 변경할 때만 실제 적용과 ERD 갱신을 함께 검토한다.

실행 순서·태스크별 결과는 docs/plan, 구조·데이터 계약은 docs/design, 날짜순 개발 기록은 docs/log, 시험 입력·원시 결과는 docs/tests에 둔다. 사용자 서비스·캐시·원본을 보존하며 클라우드 실행과 추가 모델 다운로드는 해당 작업 범위에서 진행한다.
