# 복지서비스 RAG: 피처 선별표

> **원본**: `한국사회보장정보원_복지서비스정보_20250722.csv` (367행 × 10열, **CP949 인코딩**, 기준연도 2025, 최종수정일 2025-02-20 ~ 2025-07-15)
> **상세 설계**: [welfare-rag-pipeline-design.md](welfare-rag-pipeline-design.md)

## 0. 먼저 알아야 할 점

1. **CSV에는 `신청자격`, `복지내용` 컬럼이 없습니다.** 설명 텍스트는 `서비스요약` 하나뿐입니다(평균 64자). 게다가 대부분 "~을 도모합니다" 식의 목적 문장입니다.
2. **요약만으로는 서비스를 구분할 수 없는 경우가 있습니다.** 의료급여 계열 6개 서비스는 요약 문장이 글자 하나 다르지 않고 똑같고, 공백을 정리하면 2건이 더 겹쳐 8건이 문장 2개를 나눠 씁니다. 그래서 **서비스명을 반드시 함께 임베딩**합니다.
3. 신청자격과 복지내용은 **같은 `서비스아이디`(WLF…)로 `중앙부처복지서비스` OpenAPI 상세조회를 호출해 보강**합니다(선택 단계). 보강하지 않으면 챗봇은 "어떤 서비스가 있는지"까지만 답할 수 있고, "내가 대상인지"에는 답할 수 없습니다.

범례: 🟢 임베딩(의미검색 대상 텍스트) · 🔵 메타데이터 필터 · ⚪ 표시/출처(LLM 컨텍스트와 응답 카드용) · ❌ 제외

## 2. 보강 필드 (신청자격, 복지내용): OpenAPI 상세조회

`GET https://apis.data.go.kr/B554287/NationalWelfareInformationsV001/NationalWelfaredetailedV001?servId=WLF…`

| 구분 | API 필드 | 역할 | 청크 섹션 |
|---|---|---|---|
| **신청자격** | 지원대상 `tgtrDtlCn` | 🟢 | `target` |
| **신청자격** | 선정기준 `slctCritCn` | 🟢 | `criteria` |
| **복지내용** | 서비스내용 `alwServCn` | 🟢 | `benefit` |
| 신청 | 신청방법 `applmetList` | ⚪ | 임베딩하지 않습니다. "주민센터 방문 신청" 같은 문구가 거의 모든 서비스에 반복되어 검색 변별력이 떨어집니다 |
| 분류 | 생애주기 `lifeArray`, 가구상황 `trgterIndvdlArray`, 관심주제 `intrsThemaArray` | 🔵 + 🟢(태그 줄) | `overview` |
| 분류 | 제공유형 `srvPvsnNm`, 지원주기 `sprtCycNm`, 온라인신청 `onapPsbltYn` | 🔵 | 없음 |
| 기타 | 문의처, 관련 홈페이지, 근거법령, 서식 목록 | ⚪/❌ | 없음 |

> 필드명은 공개 사례 기준입니다. 구현 전에 공공데이터포털 Swagger 명세로 최종 확인하세요.

## 3. 임베딩 텍스트 템플릿

**overview 청크** (서비스당 1개, CSV만으로 만들 수 있음)
```
서비스명: 장애인연금
분류: 보건복지부 > 장애인자립기반과
요약: 장애로 인하여 생활이 어려운 중증장애인에게 매월 일정금액의 연금을 지급하여 생활안정 지원과 복지 증진 및 사회통합을 도모합니다.
태그: 생애주기=… | 가구상황=… | 관심주제=… | 제공유형=…      ← 보강했을 때만
```

**섹션 청크** (보강했을 때, 섹션마다 1개 이상. 500자를 넘으면 분할)
```
[장애인연금] 지원대상
…tgtrDtlCn 원문…
```
→ 모든 청크 맨 앞에 `[서비스명]` 헤더를 붙입니다. 조각 하나만 검색되어도 어느 서비스 이야기인지 알 수 있게 하기 위해서입니다.
